# S03 — «Слушать альбом» из каталога зависит от первого трека и замораживает очередь

**Приоритет:** P1 · **Область:** `client/src/lib/search/play-remote.ts`, `client/src/screens/catalog.tsx` · **Зависит от:** S01

## Проблема

«Слушать альбом» (`wholeAlbum: true`) в `AlbumBody` строит запрос от первого трека треклиста (`request(first, true)`),
и вся логика ожидания следит **только за ним**:

1. **Первый трек не нашёлся — альбом «не найден».** Если источник нашёлся для треков 2…N, а для первого нет (бонус,
   скрытый трек, другой мастеринг) — `check()` видит `not_found` первого и показывает toast «Не найден источник для
   «<альбом>»», хотя половина альбома играбельна. Ничего не играет.
2. **Уже играбельные треки игнорируются.** Альбом открывали/слушали раньше: треки 3–10 `found`, первый — `not_found`.
   «Слушать альбом» не играет сразу доступное, а ставит ожидание первого (и снова п. 1).
3. **Очередь замораживается в момент старта.** `start()` берёт `albumTracks(...).filter(canPlay)` в момент, когда
   первый трек стал играбельным. Треки, найденные позже (другая раздача, CUE, вторая волна проверок), в очередь не
   попадают — альбом обрывается посреди.
4. Если первый трек уже играбелен (`own && canPlay`), запрос `POST /api/play` для альбома уходит в фоне, но очередь —
   снова снимок «что доступно сейчас».

## Текущее состояние (прочитай перед началом)

- `client/src/lib/search/play-remote.ts` — `playInput`, `start`, `check`, `playRemote` (ветки `wholeAlbum`).
- `client/src/screens/catalog.tsx` — `AlbumBody`, `request(first, true)`.
- Контроллер плеера: `client/src/lib/player/controller.ts` — `startCurrent`/`canPlayQueued` (плеер уже умеет держать в
  очереди трек, который ещё не `found`, и ждать его) и `nextPlayableIndex`.
- `client/src/lib/player/queues.ts` — как строятся очереди альбома в библиотеке (`PlayAlbumButton`).

## Что сделать

1. Ожидание «альбома» отделить от ожидания «трека»: `Pending` для `wholeAlbum` хранит `albumMbid` и после ответа
   сервера — `album_id` и `track_ids` (весь треклист).
2. `check()` для альбома: играть, как только **любой** трек альбома играбелен — с первого играбельного по порядку
   треклиста. «Не найден» — только когда ни один трек альбома не ищется (`adding`) и ни один не играбелен.
3. Очередь альбома — **весь треклист** (`toPlayerTrack` для всех `track_ids`), а не снимок играбельных: контроллер
   сам пропускает/ждёт неготовые (`canPlayQueued`, `nextPlayableIndex`). Проверь, что пропуск ненайденных при
   `ended` работает и для треков, ставших `found` позже. Если контроллер так не умеет — минимальная доработка в нём,
   с тестом.
4. Нажатие на отдельный трек в каталоге с `context: 'album'` — та же очередь (весь треклист с текущей позиции), чтобы
   «нажал трек 5» продолжался треками 6…N, даже если они найдутся позже.

## Тесты (обязательные)

`play-remote.test.ts`:

- `whole_album_plays_first_playable_when_first_track_not_found`: трек 1 `not_found`, трек 2 `found` → играет трек 2,
  без toast об ошибке.
- `whole_album_plays_available_immediately`: до нажатия треки 3–5 `found`, трек 1 `not_found` → играет трек 3 сразу
  (в обработчике клика), запрос на альбом отправлен.
- `whole_album_reports_no_source_only_when_nothing_left`: все треки `not_found` после `adding` → один toast.
- `album_queue_contains_whole_tracklist`: очередь — все треки; трек, ставший `found` после старта, играет по `ended`
  предыдущего (тест контроллера, если понадобилась доработка).
