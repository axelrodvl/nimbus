# F07 — Фильтр библиотеки теряет символы при наборе

**Приоритет:** P1 (баг) · **Область:** `client/src/screens/library/library.tsx` · **Зависит от:** —

## Проблема

Поле «Поиск в библиотеке» на `/library/:tab` — управляемый `<input>`, чьё значение берётся **из URL**
(`value={params.get('q')}`), а `onChange` вызывает `setParams(next, { replace: true })`. Навигация React Router
обновляет состояние роутера в переходе (`startTransition`) — новое значение поля приходит в DOM только после рендера
экрана с отфильтрованным списком. Если следующее нажатие случилось раньше, React восстанавливает в поле прежнее
значение из URL и набранный символ пропадает (курсор тоже прыгает в конец).

Воспроизведение (ревью 2026-11-20, `vite preview`, мок на 60 000 треков, Playwright `keyboard.type('album 12 zeta')`):

| Вкладка | Пауза между нажатиями | CPU | В поле |
|---|---|---|---|
| Альбомы | 5 мс | ×1 | `alm 2zta` |
| Треки | 5 мс | ×1 | `a 12ea` |
| Треки | 80 мс (обычный набор) | ×4 (средний телефон) | `abum 12 zeta` |
| Треки | 150 мс | ×4 | `album 12 zeta` |

Экран поиска (`screens/search.tsx`) этой проблемы не имеет: там поле держит локальное состояние, а URL обновляется
из него. На телефоне с большой библиотекой фильтр «съедает» буквы при обычной скорости набора.

## Текущее состояние (прочитай перед началом)

- `client/src/screens/library/library.tsx` — `LibraryScreen`, обработчик `onChange` поля.
- `client/src/screens/search.tsx` — образец: `useState(urlQuery)` + синхронизация с `?q=` в обе стороны
  (`prevUrl`), `setParams(..., { replace: true })`.
- `client/src/lib/library/use-filtered-list.ts` — фильтр уже использует `useDeferredValue(q)`.
- `client/src/lib/library/tabs.ts` — `libraryHref` (ссылки вкладок и фильтров несут `q`).
- Тесты: `client/src/screens/library/*.test.tsx`, e2e `client/tests/e2e/library.spec.ts`.

## Что сделать

1. Поле держит значение в локальном состоянии (`useState(urlQuery)`); ввод меняет его сразу.
2. URL обновляется из локального значения (`replace: true`, без записей в истории) — в обработчике, как в поиске,
   или с короткой задержкой; список фильтруется по локальному значению через `useDeferredValue` (как сейчас по `q`).
3. Внешняя смена `?q=` (назад/вперёд, ссылка вкладки или фильтра статуса с `q`) переносится в поле (паттерн `prevUrl`
   из `search.tsx`); набор текста этой веткой не перетирается.
4. Ссылки вкладок и фильтров (`libraryHref(..., { q })`) берут локальное значение — переход на другую вкладку во время
   набора не теряет последние символы.
5. Проверь, нет ли других управляемых полей со значением из URL (`grep setParams`/`useSearchParams`); на момент
   ревью — только это.

## Тесты (обязательные)

- Компонентный тест: быстрый ввод (`userEvent.type` без задержки) на большом store (≥ 5 000 треков, вкладка «Треки») —
  в поле ровно набранная строка, `?q=` в итоге совпадает.
- Внешняя смена `?q=` (навигация на `/library/tracks?q=abc`) — поле показывает `abc`.
- Переключение вкладки во время набора сохраняет запрос.
- e2e `library.spec.ts`: `keyboard.type('album 12 zeta', { delay: 5 })` во вкладке «Треки» большой библиотеки — значение
  поля и `?q=` совпадают с набранным.

## Критерии приёмки

- `just check`, `just client-test`, `just client-e2e` (затронутые спеки) зелёные.
- Ручная проверка с троттлингом CPU ×4: набор с паузой 80 мс не теряет символов.
