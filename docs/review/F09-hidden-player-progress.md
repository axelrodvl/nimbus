# F09 — Невидимые части плеера обновляют прогресс 10 раз в секунду

**Приоритет:** P3 (производительность) · **Область:** `client/src/components/player/*` · **Зависит от:** —

## Проблема

Во время воспроизведения позиция читается по `requestAnimationFrame` раз в 100 мс (`createProgressSource`), и каждый
подписчик `useProgress` перерисовывается. Подписчиков три, а видим один:

- `PlayerBar` (`hidden sm:block`) — виден на планшете и десктопе;
- `MiniPlayer` (`sm:hidden`) — виден на телефоне, на десктопе скрыт CSS, но смонтирован и перерисовывается;
- `FullPlayer` — смонтирован **закрытым** (`open={fullOpen && hasTrack}`) и тоже перерисовывает свою полосу.

Замер (ревью 2026-11-20, MutationObserver за 3 с воспроизведения, десктоп 1440 px): мутации идут в трёх полосах —
`player-seek` (видимая), `mini-player` и `full-player` (обе невидимы) — по 14 обновлений `value`/`style` и 28 записей
атрибутов `name`/`type` (React переустанавливает их у `input[type=range]`) в каждой. Двойная лишняя работа React и DOM
10 раз в секунду всё время воспроизведения; на телефоне — лишний расход батареи.

## Текущее состояние (прочитай перед началом)

- `client/src/lib/player/progress.ts` — `createProgressSource`, `PROGRESS_INTERVAL_MS`.
- `client/src/lib/player/hooks.ts` — `useProgress` (новый источник на каждый компонент — `useMemo` в каждом).
- `client/src/components/player/progress-row.tsx`, `seek-bar.tsx`, `player.tsx`, `player-bar.tsx`, `mini-player.tsx`,
  `full-player.tsx`.
- `client/src/components/ui/use-media-query.ts` — уже есть хук медиазапроса.
- Тесты: `client/src/components/player/player.test.tsx`, `client/src/lib/player/player-lib.test.tsx`.

## Что сделать

1. **Закрытый полноэкранный плеер не подписан на прогресс.** `ProgressRow` в `FullPlayer` рендерится только при
   `open` (или `useProgress(enabled)` возвращает замороженный снимок без подписки, пока плеер закрыт). Анимация
   открытия начинается с актуальной позиции (`getSnapshot` при монтировании).
2. **Скрытый по брейкпоинту вариант не подписан.** `MiniPlayer`/`PlayerBar` выбираются по `useMediaQuery('(min-width:
   640px)')` (тот же брейкпоинт `sm`), невидимый не монтируется вовсе — либо монтируется без `ProgressRow`. Проверь,
   что тесты и e2e, которые ищут элементы обоих вариантов, переведены на нужный вьюпорт.
3. **Один источник позиции.** `createProgressSource` — один на контроллер (модульный кэш по `ctl`), а не `useMemo` в
   каждом компоненте: один цикл rAF при любом числе подписчиков.
4. `SeekBar`: не передавать в `<input>` неизменные атрибуты при каждом тике (вынести полосу-рисунок, которая зависит
   от `value`, в отдельный дочерний компонент, а `<input>` обновлять только `value`) — если после п. 1–3 мутаций
   `name`/`type` больше нет, этот пункт можно пропустить, отметив в Журнале.

## Тесты (обязательные)

- `player.test.tsx`: закрытый полноэкранный плеер — нет подписки на прогресс (`subscribe` источника вызван один раз,
  для видимой полосы); после открытия полоса показывает текущую позицию.
- Десктопный вьюпорт: в DOM нет `ProgressRow` мини-плеера; мобильный — нет полосы `PlayerBar`.
- Один цикл rAF при двух подписчиках (подсчёт вызовов `requestAnimationFrame` в фейковом времени).

## Критерии приёмки

- `just check`, `just client-test`, `just client-e2e` (`player.spec.ts`, `mobile.spec.ts`, `full-player.spec.ts`)
  зелёные.
- В Журнале — замер MutationObserver за 3 с воспроизведения «до/после»: мутации только в видимой полосе.
