# S05 — Отложенный старт трека вне жеста: на iOS трек может не заиграть

**Приоритет:** P2 · **Область:** `client/src/lib/search/play-remote.ts`, `client/src/lib/player/audio/web-engine.ts` · **Зависит от:** —

## Проблема

`play-remote` прямо пишет: «Уже на сервере и доступен — сразу (в цепочке клика: iOS требует жеста для звука)». Но
основной сценарий — источника ещё нет — запускает трек **позже**, из подписки на store (`check()` → `start()` →
`player().play()`), вне пользовательского жеста. Safari на iOS разрешает `HTMLAudioElement.play()` без жеста только
элементу, который уже воспроизводился по жесту. Если это первое воспроизведение после открытия PWA (самый частый
случай: открыл приложение → поиск → нажал трек), `engine.play()` отклоняется (`NotAllowedError`),
`controller.resume`/`loadAndPlay` ставит `PLAYING = false` — трек молча загружен на паузе. Toast ожидания к этому
моменту давно скрыт; пользователь видит «ничего не произошло».

То же касается `controller.startCurrent`, который ждёт `found` для трека очереди, — но там старт обычно уже после
воспроизведения по жесту.

Находка получена чтением кода: на устройстве не проверялась — задача начинается с воспроизведения.

## Что сделать

1. Воспроизвести на iOS Safari / PWA (или задокументировать невозможность в этой среде и опираться на известное
   поведение WebKit) — запиши результат в Журнал.
2. **«Разблокировать» аудиоэлемент в жесте.** Метод движка `prime()` (необязательный в `AudioEngine`, в
   web-движке — реализация): если элемент ещё ни разу не воспроизводился в этой сессии и сейчас ничего не играет —
   синхронно в обработчике клика `audio.src = <короткая тишина data:URI>; audio.play().then(pause)`. Вызывать из
   `RemotePlayRow`/кнопки «Слушать альбом» до постановки ожидания. Не трогать элемент, если что-то играет.
3. **Если старт всё же отклонён** — не молчать: toast «Источник найден — нажмите ▶, чтобы слушать» с кнопкой
   «Играть» (жест → `player().resume()`), трек остаётся текущим в плеере.
4. Добавить пункт в `docs/device-checklist.md`: «Свежий запуск PWA → поиск → нажать трек без источника → трек
   заигрывает сам».

## Тесты (обязательные)

- `web-engine.test.ts`: `prime()` на нетронутом элементе вызывает `play()` и затем `pause()`; при уже играющем — ничего.
- `play-remote.test.ts`: `play` отклонён (фейк контроллера сообщает `PLAYING=false` после старта из `check`) → toast

- `remote-play` компонентный тест: клик вызывает `prime` до `playRemote`.
