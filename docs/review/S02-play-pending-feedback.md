# S02 — Пользователь ждёт запуска трека без обратной связи

**Приоритет:** P1 · **Область:** `client/src/lib/search/play-remote.ts`, `client/src/components/search/remote-play.tsx`,
`client/src/screens/catalog.tsx`, плеер (`client/src/components/player/`) · **Зависит от:** S01

## Проблема

Поиск источника для трека из поиска — это поиск раздач у провайдеров, загрузка метаданных и проверка
(`discover_album` → `verify_torrent`), минуты; при сбое провайдеров задача повторяется с паузами (`inconclusive`)
— десятки минут. Что видит пользователь:

1. **Toast ожидания висит 8 с** (`WAITING_TOAST_MS`), дальше — только спиннер поверх обложки в строке. Ушёл с
   экрана поиска/каталога — **нигде не видно**, что что-то ждёт; через несколько минут трек внезапно начинает играть
   на другом экране.
2. **Кнопка «Слушать альбом»** в каталоге (`catalog-play-album`) не показывает ожидание (спиннер — только у строки
   первого трека, `usePlayPending(mbid)`). Нетерпеливое повторное нажатие («ничего не происходит») попадает в ветку
   «повторное нажатие на то же — отмена» и **молча отменяет** ожидание: toast исчезает, никакого сообщения.
3. То же для строки трека: двойное касание на телефоне отменяет без подтверждения.
4. **Нет стадии и срока.** Сервер шлёт `job.progress` (`searching`/`verifying`, `done/total`) по альбому — клиент
   их уже хранит (`LiveStore`, `AlbumProgress`), но ожидание их не показывает. Нет и сообщения «ищем дольше обычного» /
   «провайдеры не отвечают, повторим позже».

## Что сделать

1. **Глобальный индикатор ожидания.** Пока `pending` не пуст — в зоне мини-плеера (на десктопе — в панели плеера)
   строка «Ищем источник для «…»» + стадия + кнопка «Отмена». Если плеер пуст — индикатор занимает место мини-плеера;
   если что-то играет — компактная плашка над ним. Видна на любом экране.
2. **Стадия.** Ожиданию нужен `album_id` (известен из ответа `POST /api/play`); по `AlbumProgress` этого альбома
   показывать «Ищем раздачи…» / «Проверяем раздачи: N из M». Через `SLOW_PENDING_MS` (≈45 с) без итога — дополнительный
   текст «Это может занять несколько минут — трек заиграет сам».
3. **Кнопка «Слушать альбом»** — `aria-busy`, спиннер вместо иконки и текст «Ищем…», пока ждёт именно альбом
   (`pending.request.wholeAlbum && albumMbid === album.mbid`). Состояние ожидания вынести в хук, ключ — запрос целиком,
   а не только `mbid` (см. также S08, п. 1).
4. **Отмена — явная.** Повторное нажатие на ожидающий трек/альбом отменяет, но показывает короткий toast
   «Ожидание отменено» (`info`, 2–3 с), чтобы отмена не была молчаливой. Кнопка «Отмена» в индикаторе — то же.
5. **Внезапный старт.** Если ожидание завершилось, когда пользователь уже на другом экране, — toast «Играет «…»»
   (короткий), чтобы звук не появлялся «из ниоткуда».

## Тесты (обязательные)

- Компонентный тест индикатора: `pending` → индикатор виден на экране библиотеки (не только в поиске); «Отмена»
  снимает ожидание и показывает toast отмены.
- `play_album_button_shows_pending`: нажатие `catalog-play-album` → кнопка `aria-busy`, повторное нажатие → toast отмены.
- Стадия: `AlbumProgress { stage: 'verifying', done: 2, total: 5 }` для `album_id` ожидания → текст «2 из 5».
- `slow_pending_hint` на фейковых таймерах.
- e2e (`client/tests/e2e/search.spec.ts`, мок-бэкенд): нажать трек, перейти в библиотеку, индикатор виден; мок
  переводит трек в `found` → играет, toast «Играет».
- `just client-audit` — новые элементы проходят axe и клавиатуру.

## Критерии приёмки

- `just check`, `just client-test`, `just client-e2e`, `just client-audit` зелёные.
- Скриншоты матрицы аудита с индикатором (светлая/тёмная, телефон/десктоп) просмотрены.

## Не входит

- Корректность распознавания итога (S01), логика «Слушать альбом» (S03).
