# S08 — Мелкие дефекты клиента вокруг поиска и «нажал — играет»

**Приоритет:** P3 · **Область:** `client/src/lib/search/`, `client/src/screens/search.tsx`, `client/src/components/` · **Зависит от:** S01, S03 (тот же файл `play-remote.ts` — делать после них)

## Проблема (по пунктам)

1. **Ожидание определяется только по `mbid` записи.** `usePlayPending(mbid)` и проверка «повторное нажатие»
   (`current.mbid === request.mbid`) не учитывают альбом/`trackId`. Одна запись встречается в нескольких строках
   (локальный и удалённый результат, сингл и альбом) — спиннер крутится у всех; нажатие на ту же запись **из другого
   альбома** отменяет ожидание вместо переключения на новый альбом.
2. **`findTrack` без альбома** (`appDeps`) на каждое изменение store, пока идёт ожидание, перебирает все треки
   (`for (const t of state.tracks.values())`, до 60 000) — при живых событиях это десятки полных проходов в секунду.
3. **Играбельный трек играет без пометки.** Ветка `own && canPlay` для одиночного трека не вызывает `POST /api/play`:
   трек, найденный «попутно» (поиск другого трека альбома), остаётся без `play_requested`. Если позже его источник
   умрёт, `discover_album` его не ищет (`Track::wanted()` = `false`). Нужно отправлять запрос в фоне, как для
   `wholeAlbum`.
4. **Побочный эффект в рендере.** `SearchScreen` вызывает `rememberQuery(urlQuery)` прямо в теле компонента (ветка
   `urlQuery !== prevUrl`). Это `setState` внешнего zustand-store во время рендера: подписчики (`useSearchHref` в
   `MobileTabBar`/`Sidebar`) обновляются синхронно → предупреждение React «Cannot update a component while rendering a
   different component» и лишний рендер оболочки. Перенести в эффект (или в обработчик, меняющий URL).
5. **Запись в `sessionStorage` на каждое событие прокрутки.** `rememberScroll` → подписчик `searchSession` →
   `JSON.stringify` + `setItem` синхронно, 60 раз в секунду на телефоне. Сохранять с троттлингом (≈250 мс) и
   принудительно на `pagehide`/уходе с экрана.
6. **Потерянный JSDoc.** В `client/src/lib/store/hooks.ts` комментарий «Треки альбомов артиста библиотеки (для
   «Слушать» в шапке артиста)» теперь стоит перед `useAlbumTracksByMbid`, а у `useArtistTracks` описания нет.
7. **Нет «Добавить в библиотеку» для того, что слушаешь.** Трек, запущенный из поиска, играет вне библиотеки; в меню
   «…» плеера (`components/player/track-menu.tsx`) есть «В плейлист», «Скачать», «К альбому», но нет «Добавить в
   библиотеку» — чтобы сохранить понравившийся трек, нужно снова искать его. Добавить пункт для `!in_library`
   (трек; при `albumId` — и «Добавить альбом»), через существующие мутации добавления.

- п. 4: рендер `SearchScreen` с `?q=` меняющимся снаружи — без `console.error` (в тестах `console.error` падает, если

- п. 7: меню плеера для трека вне библиотеки содержит «Добавить в библиотеку», нажатие вызывает мутацию.
