# S10 — Каждый открытый в каталоге альбом навсегда попадает в синхронизацию всех клиентов

**Приоритет:** P3 · **Область:** `backend/crates/api/src/catalog.rs`, `backend/crates/db/src/repo/sync.rs`, клиентский store · **Зависит от:** —

## Проблема

`GET /api/catalog/albums/{mbid}` вызывает `ensure_album`: артист, альбом и **все** треки сохраняются в БД при простом
открытии экрана (решение `f87712c` — чтобы «Слушать»/«Добавить» шли без MusicBrainz). Синхронизация
(`sync.rs`: `ARTIST_SELECT`, `ALBUM_SELECT`, `TRACK_SELECT`) отдаёт **все** строки, без фильтра по `in_library`.
Вместе с решением «ничего не удалять» (`ed187ad`) это значит:

- каждый просмотренный альбом (10–20 треков) навсегда уходит в снимок/дельту, IndexedDB и память **каждого** клиента;
- бюджеты производительности (`just client-perf`) рассчитаны на 60 000 треков **библиотеки**; при активном
  просмотре каталога каталожные строки растут без предела, а многие селекторы проходят по всем трекам
  (`recentlyPlayedAlbums`, `favorites`, поиск по store, `findTrack` в `play-remote`);
- первый снимок нового устройства тянет всю историю просмотров.

Это не ошибка сегодня, а неограниченный рост — задача сначала **измеряет**, потом решает.

- Клиент: `client/src/lib/store/selectors.ts`, `client/src/lib/store/hooks.ts` (`useAlbumTracksByMbid`),
  `client/src/screens/catalog.tsx` (использует строки store для статуса «в библиотеке»/«играет»),
  `client/src/lib/store/perf.test.ts`, `just client-perf`.

## Что сделать

1. **Замер.** В `perf.test.ts` / `client-perf` добавить сценарий «60 000 треков библиотеки + 30 000 каталожных
   (`in_library = false`, без `play_requested`, без прослушиваний)»; записать в Журнал, какие бюджеты нарушены.
2. **Решение (выбрать по замеру, записать обоснование в Журнал):**
   - *Вариант A (рекомендуемый, если бюджеты нарушены):* синхронизировать только «значимые» строки — трек
     `in_library OR play_requested OR есть прослушивание OR в плейлисте`, альбомы/артисты, на которые такие треки
     ссылаются (или `in_library`). Переход строки из значимой в незначимую — надгробие в дельте. Экран каталога
     берёт «в библиотеке/играет» из ответа `catalog_album` (+ store для значимых треков). Поднять `SYNC_SCHEMA`, если
     меняется формат.
   - *Вариант B:* если бюджеты держатся с запасом — оставить как есть, добавить `docs/backlog.md`-пункт с цифрами и
     порогом, при котором вернуться к варианту A.
3. В любом варианте: `catalog_album` не должен писать треки, если альбом уже в БД (сейчас так и есть — проверить
   тестом), и не должен порождать изменения синхронизации при повторном открытии (повторный upsert без изменений —
   без нового `sync_txid`).
