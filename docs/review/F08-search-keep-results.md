# F08 — Поиск: результаты исчезают на каждое нажатие при уточнении запроса

**Приоритет:** P2 (мигание) · **Область:** `client/src/lib/search/use-remote-search.ts`,
`client/src/components/search/search-results.tsx` · **Зависит от:** —

## Проблема

`useRemoteSearch` намеренно отдаёт `data = undefined`, как только введённый текст разошёлся с отправленным
(`current = wanted && settled === typed`, комментарий «результаты прежнего запроса сразу убираются»). При уточнении
запроса («radiohead» → «radiohead ok») каждое нажатие убирает весь блок результатов MusicBrainz, на месте — пусто или
`RemoteSkeleton` (с `key={query}` — заново монтируется и перезапускает анимацию на каждую букву), затем после
debounce 250 мс и ответа результаты возвращаются. Пользователь видит мигание всей страницы на каждую букву.

Замер (ревью 2026-11-20, `vite preview`, мок): после «radiohead» набор « ok» с паузой 400 мс — покадрово блок
`search-results` есть → нет (≈ 250–400 мс, 0 элементов списка) → есть, трижды подряд. CLS не ловит это (сдвиги
в 500 мс после ввода исключаются), но визуально это полная замена содержимого.

## Текущее состояние (прочитай перед началом)

- `client/src/lib/search/use-remote-search.ts` — `useRemoteSearch`, `current`, `loading`.
- `client/src/components/search/search-results.tsx` — `RemoteResults`, `RemoteSkeleton`, `SearchProgress`.
- `client/src/screens/search.tsx`, `client/src/components/search/command-palette.tsx` — потребители.
- Тесты: `client/src/lib/search/*.test.ts(x)`, `client/src/screens/search*.test.tsx`, e2e
  `client/tests/e2e/search.spec.ts` (проверь, какие тесты закрепляют «результаты сразу убираются» — их контракт
  меняется).

## Что сделать

1. **Прежние результаты остаются до прихода новых**, если новый запрос — продолжение прежнего (тот же префикс
   или отличается на правку в пару символов) **и** прошло меньше ~1 с: блок приглушается (`opacity-60`,
   `aria-busy`), клики по нему работают. Когда приходит ответ на новый запрос — замена без промежуточного пустого
   кадра. Реализация — `placeholderData: keepPreviousData` в `useQuery` плюс собственный признак «данные устарели»
   (`stale: boolean` в `RemoteSearch`), а не сброс `data`.
2. **Скелетон — только когда показывать нечего** (первый запрос, или запрос не связан с прежним) и ответ не пришёл
   за ~150 мс; без `key={query}` — один экземпляр на время ожидания, анимация не перезапускается на каждую букву.
3. Ошибка нового запроса и «ничего не найдено» заменяют прежние результаты как сейчас; очистка поля убирает всё сразу.
4. Палитра команд (`command-palette.tsx`) получает то же поведение (общий хук).
5. Обнови комментарий в хуке и, если описано, `docs/` (поиск) — новое правило показа.

## Тесты (обязательные)

- Хук: запрос «radiohead» с данными → ввод «radiohead o» — `data` прежние, `stale = true`; ответ на «radiohead o» —
  `data` новые, `stale = false`; ввод несвязанного «abba» — `data = undefined`, `loading = true`.
- `search-results`: при `stale` блок результатов в DOM и помечен `aria-busy`; скелетон не появляется.
- e2e `search.spec.ts`: после результатов «radiohead» дописать « ok» с паузой 300 мс — на каждом кадре (rAF-проба
  в странице) `[data-testid=search-results]` присутствует.

## Критерии приёмки

- `just check`, `just client-test`, затронутые e2e зелёные.
- В Журнале — покадровая проба «до/после» (число кадров без блока результатов при уточнении запроса).
