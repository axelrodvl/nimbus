> RuTracker search works again behind Cloudflare's browser check, thanks to a bundled FlareSolverr container.

## ✨ New

- **Search** — RuTracker passes Cloudflare's "Just a moment…" check on its own through [FlareSolverr](https://github.com/FlareSolverr/FlareSolverr): no more copying `cf_clearance` cookies and User-Agent from the browser. Set its address in *Settings → Sources → RuTracker → FlareSolverr* or `NIMBUS_FLARESOLVERR_URL`.
- **Docker** — optional `flaresolverr` and `jackett` services in docker compose, switched on with `COMPOSE_PROFILES` in `.env`; the default `.env.example` enables FlareSolverr.

## ⚡ Improved

- **Search** — Torznab indexers that do not support artist/album search (such as RuTracker in Jackett) now fall back to a plain text search instead of failing.
- **Settings** — the RuTracker connection check waits long enough for FlareSolverr to solve the challenge.

## ⚠️ Upgrade notes

- To use FlareSolverr with an existing `.env`, add `COMPOSE_PROFILES=flaresolverr` and `NIMBUS_FLARESOLVERR_URL=http://flaresolverr:8191`, then restart (`./stop.sh && ./start.sh`). Use `COMPOSE_PROFILES=flaresolverr,jackett` to also run Jackett.
- If your RuTracker login or password contains characters other than `A-Z a-z 0-9 _ . - ~` and Cloudflare blocks direct logins, paste the `bb_session` cookie into the RuTracker settings.
