# Шаг 11 — Фронтенд: библиотека, статусы, live-события

**Зависит от:** 09, 10
**Оценка:** 2 дня

## Цель

Подключить фронтенд к API библиотеки: реальное добавление из поиска, страницы «Библиотека» (артисты/альбомы/треки), страница артиста, страница альбома, бейджи статусов треков, обновление в реальном времени по WebSocket.

## Обязательно прочитать

`docs/web-inventory.md` — переиспользовать существующие компоненты next-beats (строка трека, карточка альбома, шапка страницы альбома/плейлиста, сетки). Сначала обнови `web/lib/api/schema.d.ts` (`just web-gen-api`).

## Что сделать

### 1. Server Functions (`app/actions/library.ts`)

- `addToLibrary(input)` — `POST /api/library`; после успеха `updateTag("library")` (+ `artist:{id}`/`album:{id}` при известных id). Вернуть `{ type, id, status }`. Ошибки бэкенда → понятные сообщения в toast (`mb_unavailable` → «MusicBrainz недоступен, попробуйте позже»).
- `removeFromLibrary(type, id)` — `DELETE`, `updateTag(...)`.
- Кнопка из шага 09 теперь работает; для артиста показывать toast «Импортируем дискографию…».

### 2. Функции чтения (`lib/data/library.ts`, `server-only`, `'use cache'`)

`getLibraryArtists`, `getLibraryAlbums`, `getLibraryTracks(status?)`, `getArtist(id)`, `getAlbum(id)` — с тегами `library`, `artist:{id}`, `album:{id}`; `cacheLife` короткий (статусы меняются). Пагинация — «Показать ещё» по `next_cursor` (клиентский компонент с Server Function `loadMore`).

### 3. Маршруты

- `/library` — вкладки «Артисты · Альбомы · Треки» (`?tab=`), фильтр треков по статусу (чипы: все / готовы к прослушиванию (`found`+`ready`) / ищем / не найдены).
- `/artist/[id]` — шапка (имя, градиент-аватар, число альбомов/треков, кнопка «Удалить»), сетка альбомов с мини-прогрессом статусов (`status_counts`).
- `/album/[id]` — шапка с обложкой (размер 500), название, артист (ссылка), год, тип, сводка статусов; таблица треков (диск/номер, название, длительность, статус); треки альбома, не входящие в библиотеку, показывать приглушёнными с кнопкой `+` (добавляет трек: `{type:"track", mbid: mbid_recording, album_mbid}`); кнопка «Добавить весь альбом».
- Главная `/` — «Недавно добавленные» (первые 12 альбомов) и «Готово к прослушиванию» (треки `found`/`ready`). Если пусто — CTA «Найдите музыку» (`⌘K`).
- Ссылки на эти маршруты в навигации (заменить пункты next-beats, скрытые в шаге 08).

### 4. Статус трека в UI

Компонент `<TrackStatusBadge status reason />` (иконки `lucide-react`, tooltip с пояснением):

| status | вид | tooltip |
|---|---|---|
| `adding` | анимированный спиннер `Loader2` | «Ищем раздачи…» / прогресс из `job.progress` («Проверяем раздачи 3/7») |
| `found` | `CircleDot` (акцентный цвет) | «Найдено, можно слушать» |
| `not_found` | `CircleSlash` (приглушённый красный) | по `reason`: `no_torrents` «Раздачи не найдены», `dead_torrents` «Нет сидов», `no_match` «Трек не найден в раздачах» |
| `ready` | `CheckCircle2` | «Скачано» |

Кнопка Play в строке трека активна только для `found`/`ready` (сам звук — шаг 19; сейчас вызывает `player.play(track)` из заглушки шага 08).

### 5. Live-обновления

Клиентский компонент `<LiveLibrarySync />` (в layout):
- `track.status` → локально обновить статус трека в отрисованных списках без перезапроса. Реализация: клиентский store (React context или `zustand`, если добавишь — отметь) `trackStatusOverrides: Map<track_id, {status, reason}>`, который `TrackStatusBadge` читает поверх серверного значения; плюс отложенный (debounce 2 с) `router.refresh()` для пересчёта сводок.
- `job.progress` → store `albumProgress: Map<album_id, {stage, done, total}>` для tooltip и шапки альбома.
- `library.changed` и `resync` → `router.refresh()` (debounce 1 с).
- Серверная инвалидация: Server Function `revalidateLibrary(tags[])` вызывает `updateTag` для затронутых тегов, вызывать её из `LiveLibrarySync` (debounce), чтобы `'use cache'` не отдавал устаревшее.

### 6. Пустые состояния и ошибки

Бэкенд недоступен → страницы показывают аккуратное сообщение, а не падают (`error.tsx` в сегментах).

## Тесты (Playwright, бэкенд мокается через `page.route` или поднимается реальный с БД — на твой выбор, отметь в Журнале)

- Добавление альбома из `/search` → кнопка превращается в галочку → `/library?tab=albums` показывает альбом.
- Страница альбома: треки со статусами; эмуляция WS-события `track.status` (можно поднять тестовый WS-сервер или подменить `WebSocket` через `page.addInitScript`) меняет бейдж без перезагрузки.
