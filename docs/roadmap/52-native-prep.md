# Шаг 52 — Подготовка к нативным оболочкам: адрес сервера, токен вместо cookie, CORS, подписанные ссылки на поток

**Фаза 4 · Зависит от:** 51

## Зачем

В PWA клиент и API живут на одном origin, авторизация — cookie. В нативной оболочке клиент загружается
из пакета приложения (`capacitor://localhost`, `https://localhost`, `tauri://localhost`), а сервер — где-то
в сети пользователя. Нужно: адрес сервера, который задаёт пользователь; токен в заголовке вместо cookie;
CORS для origin-ов оболочек; способ отдать поток туда, где нельзя поставить заголовок (`<audio>` в webview
на desktop). Шаг делает это на бэкенде и в клиенте и проверяет весь e2e-набор в «нативоподобном» режиме —
**до** появления самих оболочек, чтобы шаги 53–55 занимались только платформой.

## Текущее состояние

- `backend/crates/api/src/auth.rs` — статический токен `NIMBUS_API_TOKEN`; уже принимается из `Authorization: Bearer`, из cookie `nimbus_token` и (только WS) из `?token=`; `is_public`, `require_token`, `GET /api/auth/session` (шаг 34).
- Клиент: `src/lib/platform/` (`platform()`, `apiBase()`, `apiUrl()`, `wsUrl()`, `authHeaders()`; шаг 36), экран входа (шаг 38), `AudioSource.headers` (шаг 41), `Downloader` с заголовками (шаг 46).
- Клиент собирается в статический `dist/` и раздаётся бэкендом (шаг 48).

## Что сделать

### Бэкенд

1. **CORS** (`tower-http` `CorsLayer`), только для явного списка origin-ов: `NIMBUS_ALLOWED_ORIGINS` (через запятую), по умолчанию `capacitor://localhost,https://localhost,tauri://localhost,http://tauri.localhost`.
   `allow_credentials(false)` — кросс-доменные запросы авторизуются только заголовком; разрешённые заголовки: `Authorization`, `Content-Type`, `Range`, `If-Range`; открытые для чтения: `Content-Range`, `Accept-Ranges`, `ETag`, `Content-Length`, `X-Nimbus-*`. Same-origin PWA не меняется.
2. **WebSocket без cookie.** Кроме `?token=` — подпротокол `Sec-WebSocket-Protocol: nimbus.v1, nimbus.bearer.<hex-токен>` (токен не попадает в URL и журналы прокси); сервер отвечает подпротоколом `nimbus.v1`. Проверка `Origin` для WS — тот же список плюс собственный хост.
3. **Подписанные ссылки на поток.** `POST /api/tracks/{id}/stream-url` (`{ download?: bool }`) → `{ url, expires_at }`: адрес `GET /api/tracks/{id}/stream?st=<подпись>` с HMAC-SHA256 от `(track_id, download, exp)` на ключе, производном от `NIMBUS_API_TOKEN` (смена токена отзывает все ссылки); срок 12 ч. `st` принимается **только** эндпоинтом потока данного трека, сравнение за постоянное время; просроченная/чужая подпись → 401. Нужны для `<audio>` в desktop-webview (шаг 55) и как запасной вариант для нативных плееров.
4. **`GET /api/health`** дополнить `{ api_version: <целое> }` (сейчас 1) — клиент оболочки проверяет совместимость с сервером.
5. OpenAPI, `docs/api.md`, `docs/operations.md` (`NIMBUS_ALLOWED_ORIGINS`) — обновить; тест документации шага 51 должен остаться зелёным.

### Клиент

6. **Адрес сервера.** `src/lib/platform/server.ts`: в PWA адрес — текущий origin (настройки нет). В нативном режиме — `localStorage['nimbus:server']`; экран «Сервер» до экрана входа: поле адреса (нормализация схемы и `/` в конце), проверка `GET /api/health` (таймаут 5 с, понятные ошибки: не отвечает / не Nimbus / несовместимая версия API / нет HTTPS при не-локальном адресе — предупреждение, не запрет), после успеха — вход. Смена сервера — в разделе настроек «О приложении» (очищает локальные данные после подтверждения).
7. **Токен вместо cookie.** Интерфейс `SecretStore { get(), set(token), clear() }` в `src/lib/platform/`; реализации: PWA — не используется (cookie как раньше); нативный режим — пока `localStorage` (шаг 53 заменит на Keychain/Keystore). `authHeaders()` в нативном режиме → `{ Authorization: 'Bearer …' }`; вход сохраняет токен после успешного `GET /api/auth/session` с этим заголовком; выход — `clear()`; 401 → общий `onUnauthorized`.
   WebSocket в нативном режиме — подпротокол из п. 2. Все запросы `openapi-fetch` в нативном режиме идут с `credentials: 'omit'`.
8. **Источники для плеера и загрузчика.** `resolveStreamUrl` в нативном режиме кладёт заголовки в `AudioSource.headers`; если текущий `AudioEngine` не умеет заголовки (`capabilities.headers === false`, как у `web-engine`), берёт подписанную ссылку п. 3 (кэш до `expires_at − 10 мин`, заранее для следующего трека — правило жеста iOS из шага 41 сохраняется). Картинки артистов (`/api/artist-image/…`) в нативном режиме — через `apiUrl`; `<img>` не умеет заголовки, поэтому сделай этот эндпоинт публичным в `is_public` (это кэш публичных фото из внешних источников, секретов в нём нет) и отметь решение в Журнале.
9. **Нативоподобный режим для тестов.** Переменная сборки `VITE_PLATFORM_OVERRIDE` (`ios|android|desktop`) — только для e2e-сборки; `platform()` возвращает её, `isNative()` — `true`. Отдельный проект Playwright `native-like`: клиент на `:4173`, мок-бэкенд на **другом** порту без прокси (настоящий cross-origin), мок проверяет CORS и отклоняет cookie. Весь существующий e2e-набор прогоняется в этом режиме (кроме сценариев SW/установки — помечены `@web-only`).
10. Service worker, подсказка установки, `persist()`-подсказки про домашний экран — только при `platform() === 'web'`.

## Тесты (обязательные)

Бэкенд:
- CORS: preflight для разрешённого origin → 204 с нужными заголовками; неразрешённый → без `Access-Control-Allow-Origin`; `Access-Control-Allow-Credentials` отсутствует;
- WS: подпротокол с верным токеном → открыт, ответный подпротокол `nimbus.v1`; неверный → 401; чужой `Origin` → отказ; `?token=` по-прежнему работает;
- подписанные ссылки: выдача; поток по `st` с `Range`; просрочена → 401; подпись другого трека → 401; `download` в подписи не совпадает → 401; смена `NIMBUS_API_TOKEN` делает подпись недействительной; `st` не открывает другие эндпоинты;
- `health` содержит `api_version`. Покрытие не падает ниже порога.

Клиент (unit):
- нормализация адреса сервера; все ветки ошибок проверки;
- `authHeaders`/`credentials` в обоих режимах; WebSocket получает подпротокол; воркер скачивания получает заголовок;
- `resolveStreamUrl`: заголовки при `capabilities.headers`, подписанная ссылка иначе, кэш и обновление до истечения, синхронный путь для подготовленного трека;
- смена сервера очищает локальные данные.

E2E: проект `native-like` — весь набор зелёный; отдельный сценарий: экран «Сервер» → неверный адрес → ошибка → верный → вход → библиотека → воспроизведение.

## Подводные камни

- `capacitor://localhost` (iOS) и `https://localhost` (Android) — разные origin-ы одной оболочки; на Windows Tauri — `http://tauri.localhost`. Не используй `*`: при `*` браузеры не отдают заголовки ответа и не дают `Authorization`.
- `Range`-запросы из `<audio>` — не CORS-«простые»; в webview без заголовков работает только `st`, поэтому у эндпоинта потока preflight не должен требовать авторизации (`OPTIONS` уже пропускается `require_token`).
- Не логируй query-строку потока целиком (`st` — секрет на 12 ч): поправь `TraceLayer`, чтобы `st` и `token` маскировались.
- Режим `native-like` должен по-настоящему не иметь cookie: проверь в моке, что заголовок `Cookie` отсутствует, иначе тест ничего не доказывает.
