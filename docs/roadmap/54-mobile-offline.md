# Шаг 54 — Нативное офлайн-хранилище и фоновые загрузки (iOS, Android)

**Фаза 4 · Зависит от:** 53

## Зачем

В PWA офлайн-файлы живут в квоте браузера, которую система может очистить, а загрузка останавливается,
как только приложение уходит в фон. В оболочке файлы лежат в каталоге приложения без квоты, а скачивание
выполняет ОС — в фоне и после закрытия приложения. Менеджер офлайна, интерфейс и схема IndexedDB
(шаги 46–47) не меняются: подставляются реализации `OfflineStorage` и `Downloader`.

## Текущее состояние

- `client/src/lib/offline/`: интерфейсы `OfflineStorage` и `Downloader`, менеджер с веткой `downloader.background === true` (шаг 46), интерфейс офлайна (шаг 47).
- Оболочка `mobile/`, нативный плеер (принимает `file://`-источники), `SecretStore` (шаг 53); Bearer и подписанные ссылки (шаг 52).

## Что сделать

1. **Локальный плагин `mobile/plugins/nimbus-offline`** (TS + Swift + Kotlin):
   - файлы: `list`, `size`, `remove`, `usage` (`bytes` занято нами, `quota` = свободное место на диске), путь `tracks/<trackId>` в каталоге приложения;
   - загрузки: `start {trackId, url, headers, etag}`, `abort`, события `progress` (не чаще 2 раз в секунду), `done`, `error {code, retryable}` — форматы из шага 46; `pending()` — что ОС качает или докачала, пока JS не работал;
   - `networkType()` → `wifi | cellular | none` и событие смены.
   - **iOS:** каталог `Application Support/tracks` с `isExcludedFromBackup`; `URLSession` с фоновой конфигурацией (`isDiscretionary = false`, `sessionSendsLaunchEvents = true`), `resumeData` для докачки, `handleEventsForBackgroundURLSession` в `AppDelegate`; завершённые без JS загрузки сохраняются в журнал плагина и отдаются через `pending()`.
   - **Android:** `filesDir/tracks`; `WorkManager` (по задаче на файл, `setForeground` с уведомлением о прогрессе, ограничение сети `UNMETERED` при «только Wi-Fi»), докачка через `Range`/`If-Range` (OkHttp), журнал завершённых — в `pending()`.
2. **`client/src/lib/offline/native-storage.ts`, `native-downloader.ts`** — реализации интерфейсов поверх плагина; `Downloader.background = true`; `storage.source()` → `AudioSource { url: 'file://…', mode: 'direct' }` для нативного плеера (без объектных URL; `release` — ничего не делает).
   Фабрика выбирает их при `platform() ∈ {ios, android}`. Сетевые заголовки — `authHeaders()` (Bearer), без подписанных ссылок.
3. **Менеджер.** Ветка `background === true` из шага 46 становится рабочей: при старте и при возврате из фона — сверка с `pending()` (завершённые → `done`, ошибки → обычная логика повторов); при уходе в фон загрузки не прерываются; лимит одновременных загрузок отдаётся ОС (менеджер ставит в очередь всё, что разрешено лимитом места, — порциями по 20, чтобы не забивать планировщик).
4. **«Только по Wi-Fi»** теперь работает и на iOS: `networkType` плагина заменяет `navigator.connection`; флаг доступности настройки (шаг 47) берётся из `capabilities` загрузчика, а не из наличия браузерного API.
5. **Место.** Лимит по умолчанию в оболочке — 50 % свободного места, без потолка 20 ГБ из PWA; `persist()` и подсказки про домашний экран скрыты (шаг 52, п. 10). Предупреждение, когда свободного места на диске < 1 ГБ.
6. **Переход с PWA.** Файлы и закрепления из браузера в приложение не переносятся: разные песочницы, закрепления локальны для устройства (шаг 46). Вместо переноса — одноразовая подсказка в разделе «Офлайн на этом устройстве»: «Скачанное в браузере здесь недоступно» (только при первом запуске оболочки).

## Тесты (обязательные)

- Клиент (Vitest): `native-storage`/`native-downloader` с фейковым плагином; менеджер: загрузки, завершённые «пока приложение было закрыто», становятся `done` без перекачки; ошибка из `pending()` → расписание повторов; уход в фон не вызывает `abort`; «только Wi-Fi» по `networkType`; лимит по свободному месту; плеер получает `file://`-источник и режим `direct`.
- Android (JUnit + `WorkManagerTestInitHelper`): докачка с `Range`/`If-Range`, сервер проигнорировал `Range` → запись с нуля, ограничение `UNMETERED`, журнал `pending()`.
- iOS (XCTest, только macOS): журнал завершённых загрузок и сохранение `resumeData` (сессия — фейк).

## Критерии приёмки

```
just client-check && just client-test && just client-cov && just client-e2e-native
just mobile-sync && just mobile-android && (cd mobile/android && ./gradlew test)
just mobile-ios   # только на macOS
```

Ручные проверки (в чек-лист устройств и Журнал): закрепить альбом и закрыть приложение — загрузка продолжилась; авиарежим после перезагрузки телефона — альбом играет; «только Wi-Fi» на сотовой сети — очередь стоит. При недоступности SDK — `БЛОК:` как в шаге 53.

## Не входит в шаг

- Перенос файлов между PWA и приложением, синхронизация закреплений между устройствами (`docs/backlog.md`).

## Подводные камни

- Фоновая `URLSession` на iOS не работает с `dataTask` и не показывает прогресс, пока приложение приостановлено — интерфейс должен терпеть «скачок» прогресса при возврате.
- Фоновая сессия iOS не поддерживает потоки без `Content-Length` (перекодированные треки) так же хорошо, как файлы: такие загрузки допускается выполнять только на переднем плане (`resumable: false` → не ставить в фоновую сессию, а качать обычной); записать в Журнал фактическое поведение.
- Заголовок `Authorization` в фоновой сессии iOS сохраняется в задаче — при смене токена все поставленные задачи нужно отменить и поставить заново (`onLogout`/смена сервера → `clear()`).
- Android убивает `WorkManager`-задачи без `setForeground` через ~10 мин: загрузка альбома должна идти с уведомлением.

> Примечание после шага 46: реализации подставляются в `createPlatformStorage()` и `createPlatformDownloader()` (`client/src/lib/offline/index.ts`; сейчас для не-web платформ хранилище `null` → `supported = false`). Менеджер ждёт от `Downloader` сообщений `progress { bytesDone, bytesTotal, mime, etag, resumable }`, `done { bytes, mime, etag, resumable }`, `error { code, retryable, bytesDone, info? }` (`DownloadMessage`, `types.ts`); коды ошибок — `DownloadErrorCode`. Ветка `background === true`: при старте запись `downloading` с файлом нужного размера (`bytes_total`) считается `done`, иначе остаётся `downloading` и ждёт сообщений загрузчика — повторно `start` не вызывается; если ОС потеряла задачу, нужен сигнал `error` (иначе запись зависнет). `storage.source()` вызывается из плеера (кэш на два трека) и обязан работать в любой вкладке/окне; `release()` для нативных путей — пустая операция. Сетевые условия (`online`, `cellular`, подписка) — `ManagerDeps.network`; для нативных оболочек подставить значения плагина сети.
