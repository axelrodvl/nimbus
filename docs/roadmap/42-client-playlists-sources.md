# Шаг 42 — Плейлисты и источники треков

**Фаза 2 · Зависит от:** 41

## Зачем

Два оставшихся блока прежнего интерфейса: плейлисты (включая динамический «Избранное») и ручное
управление источниками (какой торрент и файл играет трек, свой magnet, повтор поиска). После шага
новый клиент покрывает всё, что умел старый, кроме настроек и экрана загрузок.

## Что сделать

### Плейлисты

1. **Вкладка «Плейлисты» в библиотеке** (добавить в массив вкладок шага 39): «Избранное» первым (если есть прослушивания), затем пользовательские по `last_used_at`; обложка плейлиста — как сейчас (сверь, откуда берётся `cover_url`: если с сервера — вычисли на клиенте тем же правилом из треков). Кнопка «Новый плейлист».
2. **Экран `/playlist/:id`** (`:id` — число или `favorites`): шапка (название, число треков, длительность), кнопка воспроизведения, виртуализированный список треков (те же `TrackRow`), удаление трека из плейлиста, удаление плейлиста (с подтверждением; для «Избранного» кнопок изменения нет).
3. **Мутации — оптимистичные (`mutate`, шаг 37):**
   - создать: запрос → после ответа с id вставить в store (до ответа — состояние ожидания в форме; временных id не вводим);

   Повторное добавление уже имеющегося трека — не ошибка (сервер идемпотентен из-за `UNIQUE`; проверь код ответа и покажи «уже в плейлисте»).
4. **Диалог «Добавить в плейлист»** (перенос `add-to-playlist-dialog.tsx`): список плейлистов по недавности использования, отметка «уже добавлен», создание нового прямо из диалога.

## Тесты (обязательные)

Unit/компонентные:
- плейлисты: порядок вкладки; «Избранное» вычисляется локально и обновляется после `played`; создание/удаление/добавление/удаление трека — оптимистично с откатом при 500;
  диалог: отметка «уже добавлен», создание из диалога добавляет трек в новый плейлист;
- источники: таблица во всех статусах метаданных; проверка magnet (валидный, без `xt`, пустой); выбор источника вызывает запрос и обновляет список; ошибки сервера показываются;
- инвалидация по событиям — с debounce (10 событий → 1 запрос);
- меню трека: набор пунктов для трека из библиотеки / в плейлисте (есть «Убрать из плейлиста») / в очереди плеера.

E2E (перенос `sources.spec.ts` + новые):
- создать плейлист → добавить два трека из альбома → открыть плейлист → воспроизвести → убрать трек → удалить плейлист;
- трек добавлен в плейлист на «другом устройстве» (`/__test/mutate` + `sync.poke`) → появился в открытом плейлисте без перезагрузки;
- прослушать трек до порога → он появился в «Избранном»;
- страница источников: добавить magnet → новая строка в таблице; повторить поиск → статусы треков `adding`;
- сменить источник трека в диалоге → бейдж подтверждения исчез;
- без сети: плейлисты открываются и играют (то, что доступно), попытка изменить → понятное сообщение, состояние не изменилось.

## Подводные камни

- `PlaylistDto.id` на сервере — строка (`"favorites"` или число строкой), в синхронизации — число. Сведи к одному типу на границе API (`src/lib/api`), внутри клиента: `number | 'favorites'`.
- «Избранное» зависит от `play_count`, который клиент увеличивает оптимистично (outbox) и позже получает с сервера — не допускай двойного учёта: оптимистичное значение заменяется серверным при дельте, а не суммируется.
- Источники — серверные данные с коротким сроком жизни: не клади их в IndexedDB.
