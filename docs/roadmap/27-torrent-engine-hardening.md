# Шаг 27 — Торрент-движок: блокировки, жизненный цикл, полное покрытие

**Фаза 1 · Зависит от:** 25 · **Закрывает находки:** T1, T3, T4, T5, T7

## Зачем

`TorrentEngine` — самое рискованное место бэкенда: сеть, диск, чужая библиотека. Сейчас один трек без
пиров блокирует весь движок на 45 секунд, фоновые задачи не отслеживаются, а половина поведения не
покрыта тестами. После шага операции над разными торрентами независимы, жизненный цикл фоновых задач
управляем, и каждое публичное поведение движка проверено тестом на локальном рое.

## Текущее состояние (прочитай целиком)

- `backend/crates/torrent/src/lib.rs` (870 строк) — `EngineConfig`, `TorrentEngine`, трейты `MetadataFetcher`, `FileProvider`.
  - `selected: Arc<Mutex<HashMap<InfoHash, HashSet<usize>>>>` — глобальный мьютекс; `ensure_file` держит его во время `session.add_torrent(...)` под таймаутом `metadata_timeout` (45 с).
  - `spawn_pause_when_done` — `tokio::spawn` на каждый вызов; `spawn_ratio_watcher` — вечный цикл без остановки.
  - `listen_port: Option<u16>`, `None` → порт 0 (случайный); в `EngineConfig::new` всегда `None`.
- `backend/crates/torrent/src/fake_swarm.rs` (feature `test-fakes`) и `tests/swarm.rs` (10 тестов) — локальный сидер librqbit.
- Потребители: `crates/api/src/stream.rs`, `downloads.rs`, `sources.rs`, `settings.rs`; `crates/worker/src/cache.rs`, `verify.rs`, `cue.rs`.
- `backend/crates/core/src/config.rs` — переменные окружения; `docker-compose.yml` пробрасывает `6881/tcp+udp`.
- Версия librqbit — в `crates/torrent/Cargo.toml`; исходники — `~/.cargo/registry/src/*/librqbit-<версия>/`. **Сверяйся с ними**, а не с памятью.

## Что сделать

1. **Блокировки уровня торрента.** Заменить глобальный мьютекс на:
   - `state: std::sync::Mutex<HashMap<InfoHash, Arc<TorrentSlot>>>` — берётся только на чтение/вставку записи, **никогда не держится через `.await`**;
   - `TorrentSlot { op: tokio::sync::Mutex<()>, selected: std::sync::Mutex<HashSet<usize>>, pause_task: Mutex<Option<AbortHandle>> }`.
   Все операции над одним торрентом (`ensure_file`, `release_file`, `pause_torrent`, `resume_torrent`, применение политики раздачи) сериализуются `slot.op`; операции над разными торрентами не ждут друг друга.
   `set_seeding`/`set_seed_ratio`/ratio-watcher проходят торренты по одному, беря `slot.op` каждого.
2. **Конкурентный `ensure_file` одного торрента.** Второй вызов для того же торрента ждёт первого (на `slot.op`)
   и затем идёт по быстрому пути «торрент уже в сессии». Добавить в API необязательный дедлайн:
   ожидание `slot.op` тоже ограничено `metadata_timeout` (ошибка `MetadataTimeout`).
3. **Очистка после таймаута добавления.** Если `add_torrent` прерван таймаутом или вернул ошибку, а торрент
   оказался в сессии и не имеет выбранных файлов — удалить его из сессии (`session.delete(.., false)`) и убрать слот.
4. **Мульти-выбор.** Добавить `ensure_files(&self, magnet, &[usize]) -> Result<TorrentHandleId>` (один
   `update_only_files` на набор) и выразить `ensure_file` через него. В трейт `FileProvider` — метод
   `ensure_files` с реализацией по умолчанию через цикл `ensure_file` (фейки не ломаются). Понадобится шагу 33.
5. **Отслеживаемые фоновые задачи.** Завести в движке `tasks: tokio_util::task::TaskTracker` + `cancel: CancellationToken`:
   - ratio-watcher — одна задача, останавливается по `cancel`;
   - «пауза по завершении» — не более одной задачи на торрент (`slot.pause_task`, предыдущая отменяется при новом `ensure_files`);
   - `shutdown()`: `cancel.cancel()` → `tasks.close(); tasks.wait()` (с таймаутом 5 с) → `session.stop()`.
6. **Восстановление торрента в ошибке.** В быстром пути `ensure_files`: если состояние торрента `Error`
   — залогировать причину и перезапустить (в librqbit: `unpause`; если не помогает — `delete(false)` + повторное добавление).
   Новая ошибка `EngineError::Storage(String)` для ошибок диска (нет места, нет прав) — чтобы API мог ответить `507`/`500` с понятным кодом.
7. **Порт входящих соединений.** Переменная `NIMBUS_TORRENT_PORT` (по умолчанию `6881`) в `core::config` → `EngineConfig.listen_port`.
   Если порт занят — предупреждение в лог и откат на случайный порт (движок должен стартовать). `.env.example`, `README.md`, `docker-compose.yml` — задокументировать/пробросить.
   В тестах и e2e порт остаётся `None`/0.
8. **Сводка состояния.** `list_torrents()` и `stats()` не должны брать блокировки слотов (только чтение из сессии) — проверь и зафиксируй тестом на отсутствие взаимоблокировки (п. «Тесты»).
9. **Документация модуля.** В шапке `lib.rs` — краткая схема: какие блокировки есть, в каком порядке берутся, какие задачи живут в фоне.

## Тесты (обязательные; локальный рой, без интернета)

Вынеси хелперы роя из `tests/swarm.rs` в `fake_swarm.rs`/`nimbus-testkit`, чтобы ими пользовались и другие крейты.
Нужен второй вид «сидера» — **глухой**: magnet с валидным info-hash, у которого нет пиров (метаданные не придут).

- **Независимость торрентов:** `ensure_file` на «глухой» magnet (висит до таймаута 2 с) и одновременно `ensure_file` + чтение стрима живого торрента — второй завершается быстро (< 1 с), не дожидаясь первого.
- **Конкурентные `ensure_file` одного торрента** (10 параллельных вызовов на разные индексы) → все успешны, `selected_files` — объединение, торрент в сессии один.
- **Идемпотентность:** повторный `ensure_file` того же индекса не вызывает `update_only_files` (проверка по отсутствию изменений/быстрому возврату).
- **Таймаут метаданных:** «глухой» magnet → `MetadataTimeout`, после чего торрента в сессии нет и слота нет.
- **`InvalidFileIndex`** для нового и для уже добавленного торрента; новый торрент при этом удаляется из сессии.
- **`ensure_files`** с несколькими индексами → все качаются; не выбранный файл не скачан (размер на диске 0/нет файла).
- **`open_stream`:** чтение с начала, `seek` в середину и в конец, данные побайтно совпадают с исходными; `open_stream` невыбранного файла → `NotFound`.
- **`release_file`:** убирает файл из выбора; последний файл → торрент удалён из сессии; `delete_data = true` удаляет файл с диска; неизвестный торрент → `NotFound`.
- **Политика раздачи:** `seeding = false` → после завершения торрент на паузе; `set_seeding(true)` → снят с паузы; `set_seeding(false)` → снова пауза; добавление нового файла в завершённый торрент на паузе → возобновляется.
- **Ratio:** `ratio_reached` — unit-тест на граничные значения; интеграционно — при достигнутом лимите watcher ставит на паузу (интервал watcher сделать настраиваемым в `EngineConfig`, в тесте 50 мс).
- **`pause_torrent`/`resume_torrent`:** состояния в `list_torrents()` меняются; для неизвестного — `NotFound`.
- **Рестарт с persistence:** скачать файл, `shutdown()`, создать движок на том же каталоге → торрент восстановлен, `selected_files` тот же, `file_progress.finished == true`, `open_stream` читает без сети (сидер к этому моменту остановлен).
- **Shutdown:** после `shutdown()` фоновые задачи завершены (`tasks.is_empty()`), повторный `shutdown()` безопасен.
- **Порт:** занятый `listen_port` → движок стартует на другом порту.

Потребители (`crates/api/tests/stream.rs`, `downloads.rs`, `crates/worker/tests/cache.rs`) должны проходить без изменения ожиданий.

## Подводные камни

- `Session::add_torrent` для уже управляемого торрента возвращает `AlreadyManaged` — используй это как страховку от гонок, а не как основной путь.
- `ManagedTorrent::wait_until_completed` завершается ошибкой при удалении торрента — задача «паузы по завершении» должна это переживать молча.
- `update_only_files` у librqbit может требовать, чтобы торрент не был в состоянии `Initializing` — если так, дождись выхода из него под `slot.op` с таймаутом.
- Тесты роя не должны использовать фиксированные порты и общий временный каталог; каждый тест — свой `tempdir`.
- Не «ускоряй» тесты уменьшением файлов до размера одного куска: нужен seek через границы кусков (оставь ≥ 1 МБ и кусок 32 КБ, как сейчас).
