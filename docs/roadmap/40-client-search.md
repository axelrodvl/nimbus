# Шаг 40 — Поиск, командная палитра, добавление в библиотеку

**Фаза 2 · Зависит от:** 39

## Зачем

Поиск — вход в приложение: через него в библиотеку попадает музыка. В новом клиенте он сначала
мгновенно ищет по локальной библиотеке, а результаты MusicBrainz подтягивает из сети; добавление
оптимистично и сразу видно в библиотеке.

## Текущее состояние (источники для переноса)

- `web/features/search/components/` — `search-view.tsx`, `search-results.tsx` (373 строки: секции артистов/альбомов/треков, состояния), `command-palette.tsx` (280 строк, ⌘K), `add-to-library-button.tsx`; `web/features/search/add-to-library.ts`.
- `web/hooks/use-search.ts` — debounce, отмена запросов, состояние.
- `web/app/(app)/search/page.tsx`; `web/components/shortcut-hint.tsx`.
- `web/app/actions/library.ts` — `addToLibrary`.
- Тесты прежнего поведения: `web/tests/search.spec.ts`, фикстура `web/tests/fixtures/search-radiohead.json`.
- Бэкенд: `GET /api/search?q=…` (`backend/crates/api/src/search.rs` — форма ответа и коды ошибок, в т. ч. недоступность MusicBrainz), `POST /api/library` (`AddToLibraryRequest { kind, mbid, album_mbid? }` → `{ kind, id, status }`).
- Локальный поиск: `searchLocal` (шаг 37).

## Что сделать

1. **Данные поиска — `src/lib/search/`.**
   - `useRemoteSearch(query)` на TanStack Query: ключ `['search', normalizedQuery]`, debounce 250 мс, отмена предыдущего запроса (`signal`), `placeholderData: keepPreviousData`,
     `staleTime` 5 минут (повторный ввод того же запроса — без сети), минимальная длина 2 символа, без автоповторов на 4xx;
   - `useLocalSearch(query)` — синхронно из store, до 5 результатов на секцию;
   - история запросов: последние 10 в `localStorage['nimbus:search-history']` (добавляется при переходе по результату или добавлении в библиотеку), очистка.
2. **Экран `/search`.** Поле ввода с автофокусом (на настольных), запрос — в URL (`?q=`), «назад» возвращает прежние результаты из кэша без запроса.
   Порядок: «В вашей библиотеке» (локальные совпадения, сразу) → секции MusicBrainz (артисты, альбомы, треки) — перенос вёрстки `search-results.tsx`.
   Состояния: пусто (история запросов и подсказка), загрузка (skeleton секций, локальные результаты уже видны), нет результатов, ошибка (сеть/MusicBrainz недоступен — с кнопкой «Повторить»),
   офлайн (только локальные результаты и пояснение).
   Результат, уже находящийся в библиотеке (сопоставление по `mbid` со store), показывается как ссылка на локальную сущность с отметкой «в библиотеке», а не с кнопкой добавления.
3. **Добавление в библиотеку.** `AddToLibraryButton` (перенос состояний: добавить → добавляется → в библиотеке/ошибка):
   `POST /api/library` → по ответу `{ id }` — `requestSync('add')`; до прихода дельты кнопка в состоянии «добавляется», после появления сущности в store — ссылка «Открыть».
   Оптимистичной вставки в store нет (локального id ещё не существует) — оптимистично только состояние кнопки; оно хранится по `mbid` в маленьком store, чтобы пережить переходы между экранами.
   Ошибка → toast с текстом из `ApiError`, кнопка возвращается в исходное состояние. Двойной клик не создаёт второй запрос.
4. **Командная палитра (⌘K / Ctrl+K, `/`).** Перенос `command-palette.tsx` на Ariakit: открытие с любого экрана, ввод ищет локально сразу и удалённо с debounce,
   навигация стрелками, Enter — перейти/добавить, Esc — закрыть, фокус возвращается на прежний элемент. Раздел «Действия»: переходы на экраны (берутся из списка зарегистрированных маршрутов оболочки), смена темы.
   Провайдер палитры подключается в оболочке (`app-shell.tsx`) — единственная правка оболочки в этом шаге; кнопка поиска в боковой панели и `ShortcutHint` (перенос).
5. **Маршрут и навигация.** Зарегистрировать `/search` (пункт «Поиск» появится сам — см. шаг 38). Ссылку пустой главной (шаг 39) перевести на `/search`.
6. **Мок и e2e.** Мок: `GET /api/search` (фикстура `search-radiohead.json` + управляемые задержка и ошибка), `POST /api/library` (создаёт сущности в данных мока, шлёт `sync.poke`).
7. **i18n.** Новые ключи («В вашей библиотеке», история, офлайн-пояснение) — во все языки.

## Тесты (обязательные)

Unit/компонентные:
- `useRemoteSearch`: debounce (быстрый ввод → один запрос), отмена устаревшего запроса, кэш (возврат к прежнему запросу без сети), короткий запрос не уходит, ошибка не повторяется на 4xx;
- история: добавление, ограничение 10, без дублей, очистка;
- результаты: локальные показываются до ответа сети; сущность из библиотеки помечена и ведёт на локальную страницу; все состояния (пусто/загрузка/нет результатов/ошибка/офлайн);
- кнопка добавления: полный цикл состояний, защита от двойного клика, откат при ошибке, состояние переживает размонтирование;
- палитра: открытие/закрытие горячими клавишами, не открывается при вводе в поле (кроме ⌘K), навигация стрелками, возврат фокуса.

E2E (перенос сценариев `web/tests/search.spec.ts` + новые):
- поиск «radiohead» → секции результатов → добавить альбом → кнопка «добавляется» → альбом появился в библиотеке без перезагрузки → кнопка стала ссылкой;
- добавление артиста → на главной появляется карточка импортируемого артиста;
- ⌘K с экрана альбома → ввести название локального трека → Enter → открыт его альбом;
- MusicBrainz недоступен (мок отвечает ошибкой) → сообщение и кнопка «Повторить», локальные результаты видны;
- офлайн → только локальные результаты;
- «назад» со страницы альбома на поиск → те же результаты, новых запросов к `/api/search` нет.

## Критерии приёмки

```
just client-check && just client-test && just client-cov && just client-e2e
```

## Не входит в шаг

- Воспроизведение из результатов поиска (шаг 41 добавит кнопки в общие компоненты строк).
- Изменение ранжирования и формы ответа `/api/search`.

## Подводные камни

- Нормализуй запрос для ключа кэша (trim, схлопывание пробелов, нижний регистр), но в URL и поле ввода оставляй исходный текст.
- `keepPreviousData` показывает результаты прошлого запроса — пометь их «устаревшими» (приглушение, как `animate-pending` в старом интерфейсе), чтобы пользователь не кликнул не туда.
- Сопоставление «уже в библиотеке» делай по индексу `mbid → id` (построй мемоизированный селектор), а не линейным поиском на каждую строку.
- Горячая клавиша `/` не должна срабатывать, когда фокус в поле ввода или открыт диалог.
