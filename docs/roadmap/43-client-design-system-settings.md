# Шаг 43 — Дизайн-система форм и новые настройки

**Фаза 2 · Зависит от:** 38 · **Закрывает находку:** F5

## Зачем

Настройки сейчас выглядят криво: глобальные стили `input`/`label` ломают чекбоксы и числовые поля,
разделы — голые формы со своей кнопкой «Сохранить» каждая, нет переключателей и выпадающих списков в
общем стиле. Шаг вводит набор примитивов форм в существующем визуальном языке и собирает на них
настройки заново — как в настоящем приложении: разделы с навигацией, строки «название — описание —
элемент управления», автосохранение.

## Что сделать

### Примитивы (`src/components/ui/`)

1. Каждый — на Ariakit, где есть подходящий компонент; стили только токенами; обе темы; состояния `hover / focus-visible / disabled / invalid`; высота элементов управления единая (40 px, на касаниях — 44 px).
   | Компонент | Назначение |
   |---|---|
   | `Field` | подпись + описание + ошибка, связывает их с элементом (`aria-describedby`, `aria-invalid`) |
   | `TextInput`, `PasswordInput` | текст; пароль — с кнопкой «показать» и режимом «секрет задан» (плейсхолдер-маска, пустое значение = не менять) |
   | `NumberInput` | число с шагом, границами, единицей измерения справа; колёсико мыши значение не меняет |
   | `Switch` | вкл/выкл (вместо чекбоксов) |
   | `Checkbox` | для наборов значений |
   | `Select` | выпадающий список (Ariakit Select), на мобильных — на всю ширину |
   | `SegmentedControl` | выбор из 2–4 вариантов |
   | `Slider` | диапазон с отображением значения |
   | `SortableList` | порядок элементов перетаскиванием **и** кнопками вверх/вниз (доступность); замена `format-order.tsx` |
   | `ProgressBar`, `Badge`, `Tooltip` | индикаторы |
   | `Dialog`, `Sheet` | модальное окно; на мобильных — выезжающая снизу панель. `ConfirmDialog` перевести на них |
   | `Tabs` | вкладки (использовать и в библиотеке — заменить самодельные вкладки шага 39) |
   | `SettingsSection`, `SettingsRow` | карточка раздела с заголовком и описанием; строка «название + пояснение слева, элемент управления справа», на узком экране элемент уходит под текст |
2. **Галерея.** Маршрут `/dev/ui` (только в dev-сборке и в e2e-сборке по флагу `VITE_UI_GALLERY=1`): все примитивы во всех состояниях. Нужна для визуальной проверки и скриншотов.
3. Никаких глобальных стилей элементов форм. Проверь `styles/base.css` и перенесённые компоненты: поля ввода в поиске, входе, диалогах перевести на `TextInput`.

### Настройки

4. **Данные — `src/lib/settings/`.** `useSettings()` (TanStack Query, `GET /api/settings`), `useUpdateSettings()` — частичный патч `PUT /api/settings`, оптимистичное обновление кэша, откат при ошибке.
   Ошибка валидации (400) привязывается к полю (если сервер не сообщает поле — добавь в `ApiError` бэкенда необязательное `field` и верни его из валидации настроек; это единственная правка бэкенда в шаге, с тестом).
   **Автосохранение:** переключатели/списки — сразу; текст/числа — по `blur` или Enter, с debounce 600 мс для слайдеров. Индикатор у раздела: «Сохраняется… / Сохранено / Ошибка».
   Секретные поля сохраняются только кнопкой «Сохранить» в своей строке (чтобы не отправить недописанный пароль).
5. **Макет `/settings/:section?`.** Настольный: слева список разделов, справа содержимое. Мобильный: `/settings` — список разделов, `/settings/:section` — раздел с кнопкой «назад».
   Разделы:
   - **Источники** — The Pirate Bay (Switch + «Проверить»), Torznab (URL, ключ, «Проверить»), RuTracker (логин, пароль, cookie, прокси, «Проверить»). Результат проверки — `Badge` в строке (успех/ошибка с текстом).
     Если ответ `PUT` содержит `suggest_retry_missing: true` (шаг 32) — toast с действием «Повторить поиск ненайденного» (`POST /api/acquisition/retry { scope: "missing" }`).
   - **Поиск и сопоставление** — число кандидатов, порядок форматов (`SortableList`), пропускаемые типы релизов (при включении ранее пропускавшегося типа — диалог переимпорта из `section-form.tsx`), пороги `accept`/`confirm` (слайдеры 0…1, шаг 0.01, проверка `confirm ≤ accept` — сверь с валидацией сервера), автоповтор поиска.
   - **MusicBrainz** — адрес, запросов в секунду, burst, параллельность; пояснение про публичный лимит и своё зеркало; кнопка «Сбросить к публичному».
   - **Воспроизведение** — предзагрузка следующего, перекодирование ALAC, кодек для несовместимых форматов.
   - **Хранилище сервера** — заполненность (`GET /api/storage`: использовано / лимит / закреплено, `ProgressBar`, предупреждение `over_limit`), лимит кэша, раздача и коэффициент, автозагрузка добавленного.
   - **Производительность** — параллельность поиска/проверки/импорта/метаданных/загрузок, таймаут метаданных; у каждого — допустимый диапазон из сервера и кнопка «По умолчанию».
   - **Внешний вид** — тема (`SegmentedControl`), язык (`Select`); перенести из боковой панели (там оставить только компактный переключатель темы).
   - **О приложении** — версия клиента и сервера (`/api/health`), состояние синхронизации, «Сбросить локальные данные и синхронизировать заново», выход (`logout`).
   Раздел «Офлайн на этом устройстве» добавит шаг 47; ссылку на экран «Загрузки» — шаг 44 (список разделов — массив, как вкладки и пункты навигации).
6. **Состояния экрана.** Загрузка — skeleton строк; ошибка загрузки — `ErrorState` с повтором; офлайн — настройки сервера только для чтения с пояснением, «Внешний вид» и «О приложении» работают.
7. **Маршруты.** Зарегистрировать `/settings`, `/settings/:section`.
8. **Мок и e2e.** Мок: `GET/PUT /api/settings` (с валидацией диапазонов и маскированием секретов), `GET /api/storage`, проверка провайдера, переимпорт.
9. **i18n.** Названия и описания всех строк настроек — во все 14 языков. Описания пиши по смыслу поля (что изменится для пользователя), а не повторяй название.

## Тесты (обязательные)

Компонентные — на каждый примитив: рендер, управление с клавиатуры (Tab, пробел/Enter, стрелки для `Select`/`Slider`/`SegmentedControl`/`SortableList`), `disabled`, `invalid` + связь с текстом ошибки, доступное имя.
`NumberInput`: границы, шаг, нечисловой ввод. `PasswordInput`: режим «секрет задан» не отправляет маску.

Настройки:
- автосохранение: переключатель → один `PUT` с патчем только этого поля; текст — по `blur`; слайдер — один запрос после серии движений (fake timers);
- оптимистичное обновление и откат при 500; ошибка 400 показана у нужного поля;
- секрет: пустое поле не меняет значение; новое значение уходит только по кнопке;
- диалог переимпорта появляется только при включении ранее пропускавшегося типа;
- поле, которого нет в схеме, не отображается (тест на условный рендер по наличию ключа в ответе);
- офлайн — поля только для чтения.

E2E (перенос `settings.spec.ts` + новые):
- изменить лимит кэша и порядок форматов → перезагрузка → значения сохранены;
- «Проверить» провайдера: успех и ошибка;
- мобильный размер: список разделов → раздел → «назад»;
- скриншоты `/dev/ui` и каждого раздела настроек в светлой и тёмной теме на 390 px и 1440 px — сохранить в артефакты теста и **просмотреть** (инструмент чтения изображений): выравнивание строк, одинаковая высота элементов, нет обрезанного текста (проверь на `de` и `ru` — самые длинные строки).

## Подводные камни

- Ariakit `Select` рендерит всплывающий список в портале — проверь тёмную тему (класс `dark` на `<html>`, портал наследует) и работу внутри `Dialog`.
- Автосохранение + оптимистичный кэш: ответ на старый запрос не должен затирать более новое значение — отменяй/игнорируй устаревшие ответы (у TanStack Query: `cancelQueries` в `onMutate` и последовательное выполнение мутаций одного раздела через `scope`).
- Сервер возвращает секреты замаскированными — никогда не отправляй маску обратно как значение (в старом коде для этого `SECRET_MASK`; сверь логику с `settings.rs`).
- Перетаскивание на касаниях конфликтует с прокруткой — у `SortableList` перетаскивание начинается только с «ручки».
