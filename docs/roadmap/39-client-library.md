# Шаг 39 — Экраны библиотеки: главная, библиотека, артист, альбом

**Фаза 2 · Зависит от:** 38 · **Закрывает находки:** F1, F7

## Зачем

Основные экраны, на которых пользователь проводит время. Они читают данные только из локального
store, поэтому открываются мгновенно и работают без сети; длинные списки виртуализированы и не
подгружаются страницами.

5. **Артист `/artist/:id`.** Шапка (аватар, имя, счётчики), альбомы по группам типа релиза и году (как сейчас), кнопка удаления из библиотеки.
   **Статус импорта** (`ArtistImportStatus`) — единственные данные экрана не из store: `GET /api/artists/{id}` через TanStack Query (`useArtistImport(id)`),
   запрашивается только если артист добавлен недавно или импорт виден в ответе; обновление — по событиям `library.changed`/`job.progress` для этого артиста (инвалидация с debounce 1 с). Кнопка «Повторить импорт» → `POST /api/artists/{id}/import`.
6. **Альбом `/album/:id`.** Шапка (обложка, название, артист-ссылка, год, тип, сводка статусов, `AlbumProgress` из `live`-store), список треков по дискам,

7. **Нет такой сущности.** Если `hydrated` и id нет в store — экран «не найдено» (перенос `not-found.tsx`). Если ещё не `hydrated` — skeleton того же макета (перенеси существующие skeleton-варианты; сверь размеры, чтобы не было сдвига вёрстки).
8. **Удаление из библиотеки.** Оптимистично через `mutate` (шаг 37): сущность помечается `in_library: false` в store → `DELETE /api/library/{type}/{id}` → при ошибке откат и toast.
   Подтверждение — `ConfirmDialog` (перенос текста и поведения).
9. **Мок и e2e.** Мок получает `GET /api/artists/{id}`, `POST /api/artists/{id}/import`, `DELETE /api/library/{type}/{id}`; служебный маршрут для заливки большой библиотеки (`POST /__test/seed?artists=&albums=&tracks=`).
10. **i18n.** Все строки — существующие ключи словарей; новые ключи (фильтр, счётчики) добавить во все 14 языков.

## Тесты (обязательные)

Компонентные (Vitest + Testing Library, store из фабрик):
- главная: три секции с правильным содержимым и порядком; пустая библиотека → пустое состояние;
- библиотека: вкладки, счётчики, фильтр по статусу и подстроке, состояние в URL;
- альбом: группировка по дискам, сводка статусов, `track.status` меняет бейдж без перезагрузки, `job.progress` показывает прогресс и скрывается по завершении;
- артист: группы альбомов, статус импорта во всех состояниях (`importing`, `retrying`, `failed`, нет) — перенеси случаи из `import-status.spec.ts`;
- удаление: оптимистичное скрытие, откат при 500;
- «не найдено» против skeleton до гидратации;
- виртуальный список: при 10 000 элементов в DOM не больше видимых + overscan; прокрутка к середине показывает правильные элементы.

E2E:
- переходы главная → альбом → артист → назад → назад: каждый экран отображается без единого запроса к `/api` за данными библиотеки (проверить по журналу мока: за время переходов нет новых запросов, кроме статуса импорта);
- «назад» восстанавливает позицию прокрутки в длинном списке треков;
- **мгновенность:** при библиотеке 2 000 альбомов / 25 000 треков (seed) переход между экранами < 100 мс от клика до появления шапки (измерение `performance.now()` в тесте; порог с запасом для CI — 300 мс);
- удаление альбома из библиотеки → исчезает из списка, после перезагрузки страницы его нет;
- сервер меняет статус трека (`/__test/mutate` + событие) → бейдж обновился без действий пользователя;
- без сети (`context.setOffline(true)` после загрузки): переходы между экранами работают, данные на месте.

## Подводные камни

- Не подписывай весь экран на весь store: строка трека подписывается на свой трек (`useTrackView(id)`), список — на массив id. Иначе событие статуса одного трека перерисует 25 000 строк.
- Виртуализация и View Transitions: анимируй шапку/контейнер, а не элементы списка — иначе переход будет тормозить на длинных списках.
- Высота строки трека различается на мобильной и настольной вёрстке — оценка высоты должна зависеть от точки перелома, иначе прокрутка «прыгает».
- `next/image` давал оптимизацию и `priority` — в SPA первые 4–6 обложек над сгибом грузи с `loading="eager"` и `fetchpriority="high"`.
