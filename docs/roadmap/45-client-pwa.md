# Шаг 45 — PWA: service worker, офлайн-оболочка, обновления

**Фаза 2 · Зависит от:** 41 · **Закрывает находку:** F4 (оболочка)

## Зачем

Приложение должно открываться мгновенно и без сети: код и стили — из кэша service worker, данные —
из IndexedDB (шаг 37). Плюс аккуратное обновление версии и кэш обложек. Аудио офлайн — следующие шаги.

## Текущее состояние

- `web/public/sw.js` — кэш изображений (обложки Cover Art Archive / archive.org, фото артистов `/api/artist-image/`), cache-first, ограничение 2000 записей. Логику перенести.
- `web/app/manifest.webmanifest`, `web/app/icon.tsx`, `web/public/icons/`, метаданные Apple в `web/app/layout.tsx` (`apple-mobile-web-app-capable`, `black-translucent`, `apple-touch-icon`).
- `web/components/scripts/register-sw.tsx`.
- Клиент: сессия кэшируется в `localStorage` (шаг 38), движок синхронизации имеет состояние `offline` (шаг 37), outbox прослушиваний.

## Что сделать

1. **Сборка SW.** `vite-plugin-pwa` в режиме `injectManifest`, исходник `src/sw/sw.ts` (TypeScript, отдельный `tsconfig` с `lib: ["webworker"]`), `registerType: 'prompt'`.
   В dev-режиме SW выключен (`devOptions.enabled: false`); e2e идут против сборки (`vite preview`), где он есть.
2. **Precache оболочки.** `index.html`, все JS/CSS-чанки, шрифты, иконки, словарь `en`. Остальные словари — runtime-кэш (stale-while-revalidate).
   Навигационные запросы (`request.mode === 'navigate'`), кроме путей `/api/`, отвечаются закэшированным `index.html` — приложение открывается на любом маршруте без сети.
3. **Запросы, которые SW не трогает:** всё под `/api/`, **кроме** изображений артистов; WebSocket; запросы с `Range`. Аудиопоток (`/api/tracks/*/stream`) SW не перехватывает никогда.
4. **Кэш изображений.** Перенос логики `sw.js` на TypeScript: cache-first для обложек и фото артистов, непрозрачные (`opaque`) ответы допустимы, 404 не кэшируется, ограничение числа записей (поднять до 5000, вытеснение старейших).
   Имя кэша с версией; очистка старых кэшей в `activate`.
5. **Обновление версии.** `src/lib/pwa/update.ts`: регистрация SW после загрузки, проверка обновлений при старте, при возврате вкладки на передний план и раз в час.
   Новая версия найдена → toast «Доступна новая версия» с кнопкой «Обновить» (`skipWaiting` + перезагрузка). Если музыка играет — перезагрузка только по явному нажатию, никогда автоматически.
   После обновления — одноразовый toast «Обновлено до версии X». Версия сборки — константа `__APP_VERSION__` (`define` в Vite из `package.json` + короткий git-хэш, если доступен).
6. **Манифест и метаданные.** `manifest.webmanifest` через плагин: имя, цвета под обе темы, `display: standalone`, иконки (включая maskable), `start_url: '/'`, ярлыки (`shortcuts`): Поиск, Библиотека.
   В `index.html` — метатеги Apple из старого `layout.tsx`, `apple-touch-icon`. Иконку из `icon.tsx` (генерировалась Next) сохранить статическим файлом.
7. **Постоянное хранилище.** `src/lib/pwa/storage.ts`: после первого успешного входа — `navigator.storage.persist()` (один раз, результат в `localStorage`); `estimate()` для экрана «О приложении» (шаг 43: строка «Локальные данные: N МБ, хранилище постоянное: да/нет»).
8. **Поведение без сети** (проверить и довести):
   - старт без сети: оболочка из precache → сессия из `localStorage` (последнее известное состояние; если была `authenticated` — пускаем) → библиотека из IndexedDB → состояние синхронизации `offline`;
   - элементы, требующие сети (поиск MusicBrainz, добавление, изменение плейлистов, настройки сервера, источники, экран загрузок), показывают офлайн-состояние, а не бесконечный skeleton и не ошибку;
     общий хук `useOnline()` (сеть браузера **и** доступность сервера: последний запрос/сокет) и компонент `OfflineNotice`;
   - появление сети: синхронизация, отправка outbox, инвалидация запросов — без действий пользователя;
   - сервер недоступен, но интернет есть — то же поведение, текст «Сервер недоступен».
9. **Выход из учётной записи** дополнительно очищает кэш изображений и (на будущее) вызывает `offline.clear()` — оставь явную точку расширения: массив обработчиков `onLogout`, в который шаг 46 добавит свой.
10. **Установка.** На поддерживающих браузерах — перехват `beforeinstallprompt` и пункт «Установить приложение» в разделе «О приложении»; на iOS — краткая подсказка «Поделиться → На экран Домой» (показывается только в Safari вне standalone-режима).
11. **Документация.** `client/README.md`: как устроен SW, как тестировать офлайн, как сбросить (DevTools → Application).

## Тесты (обязательные)

Unit (логику SW выноси в чистые функции `src/sw/*.ts`, тестируемые без воркера):
- классификация запросов: навигация → оболочка; `/api/...` → сеть; изображение обложки/артиста → кэш; поток аудио и запросы с `Range` → не перехватываются;
- кэш изображений: попадание, промах с записью, 404 не пишется, вытеснение сверх лимита;
- `update.ts`: найдено обновление → предложение; «Обновить» → `skipWaiting` и перезагрузка; во время воспроизведения автоматической перезагрузки нет; расписание проверок (fake timers);
- `useOnline`: сеть есть/нет, сервер недоступен при наличии сети;
- `storage.ts`: `persist` вызывается один раз.

E2E (сборка + `vite preview`, Chromium):
- первая загрузка → SW активен → `context.setOffline(true)` → перезагрузка на `/album/:id` → экран альбома отображается из локальных данных;
- офлайн: поиск показывает локальные результаты и пояснение; попытка добавить в плейлист → сообщение; настройки сервера — только чтение;
- онлайн снова → индикатор исчез, выполнена дельта, отложенное прослушивание отправлено (журнал мока);
- обновление: подменить сборку новой версией (второй каталог `dist` с другим `__APP_VERSION__`, переключение — служебным маршрутом сервера предпросмотра или вторым запуском `preview` на том же порту) → появляется предложение → «Обновить» → новая версия;
- обложки: после первой загрузки и ухода в офлайн изображения на главной отображаются;
- Lighthouse (или `@lhci/cli`, категория PWA/«installable») — проходит; если инструмент недоступен в среде — проверить вручную манифест и запись в Журнал.

## Критерии приёмки

```
just client-check && just client-test && just client-cov && just client-build && just client-e2e
```

В Журнал: размер precache (число файлов, КБ), время холодного старта без сети в e2e (от навигации до появления контента).

## Не входит в шаг

- Хранение аудио и офлайн-воспроизведение (46–47).
- Push-уведомления, фоновая синхронизация (Background Sync API) — не используются.

## Подводные камни

- SW кэширует `index.html`: ошибка в логике обновления «запирает» пользователей на старой версии. Проверь сценарий обновления e2e-тестом дважды подряд (v1 → v2 → v3).
- Не кэшируй ответы `/api/` в SW: источник правды для данных — IndexedDB, двойное кэширование даёт устаревшие данные, которые трудно отлаживать.
- iOS: service worker и хранилище у установленного на домашний экран приложения и у вкладки Safari раздельные; у неустановленного сайта хранилище может быть очищено после 7 дней без посещений — поэтому подсказка об установке и `persist()`.
- Обложки приходят с другого origin без CORS → ответы `opaque`: их размер в квоте считается с большим запасом (в Chromium — мегабайты на запись). Если `estimate()` показывает аномальный рост — запрашивай обложки с `crossorigin="anonymous"` (Cover Art Archive отдаёт CORS-заголовки; проверь) и кэшируй обычные ответы.
- Старый `web/public/sw.js` зарегистрирован у существующих пользователей на том же origin: новый SW должен в `activate` удалить его кэши (`nimbus-images-v1`) — область действия та же (`/`), так что он просто заменит старый после переключения (шаг 48).
