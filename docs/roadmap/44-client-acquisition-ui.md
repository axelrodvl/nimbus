# Шаг 44 — Экран «Загрузки»: не скачанные альбомы, повтор поиска, торренты

**Фаза 2 · Зависит от:** 33, 42, 43 · **Закрывает находку:** F6

## Зачем

Пользователь должен одним взглядом видеть, что с его библиотекой: что ещё ищется, что не нашлось и
почему, что найдено, но не скачано на сервер, что качается сейчас. И действовать: повторить поиск
всего ненайденного одной кнопкой, скачать альбом, поставить загрузки на паузу, разобраться с упавшей задачей.

## Текущее состояние

- Серверные контракты: `docs/roadmap/32-acquisition-backend.md` (состояния, `GET /api/acquisition`, `/summary`, `POST /api/acquisition/retry`, событие `acquisition.changed`),
  `docs/roadmap/33-album-downloads-backend.md` (закрепление: `POST|DELETE /api/albums/{id}/download`, `/api/tracks/{id}/download`, `pause-all`/`resume-all`, расширенный `GET /api/downloads`, событие `download.progress`, поля `AcquisitionItem.download`),
  `docs/roadmap/26-jobs-reliability.md` п. 8 (`GET /api/jobs`, `POST /api/jobs/{id}/retry`). Точные типы — в `client/src/lib/api/schema.d.ts`.
- Старый экран торрентов: `web/features/downloads/components/downloads-view.tsx` (список торрентов движка, пауза/возобновление, опрос раз в 2 с), `web/app/actions/downloads.ts`.
- Примитивы форм и `Tabs` (шаг 43), виртуальные списки (шаг 39), слой источников (шаг 42: повтор альбома, свой magnet).

## Что сделать

1. **Слой данных — `src/lib/acquisition/`** (TanStack Query):
   - `useAcquisitionSummary()` — `GET /api/acquisition/summary`;
   - `useAcquisitionList(states)` — бесконечный запрос по курсору (`useInfiniteQuery`), страницы по 100;
   - `useEngineTorrents()` — `GET /api/downloads` (опрос раз в 2 с **только** пока открыта вкладка «Торренты»);
   - `useFailedJobs()` — `GET /api/jobs?state=failed`;
   - мутации: `retryMissing({ resetDead })`, `retryAlbums(ids, { resetDead })`, `pinAlbum(id)`, `unpinAlbum(id, { deleteFiles })`, `pinTrack`, `unpinTrack`, `pauseAll`, `resumeAll`, `pauseTorrent`, `resumeTorrent`, `retryJob(id)`.
   - **Живые обновления:** `acquisition.changed { album_id }` → инвалидация сводки и списков с debounce 1 с (не чаще); `download.progress` → прямое обновление строки в кэше запросов и в `live`-store (без запроса).
     При (пере)подключении сокета — инвалидация всего раздела.
2. **Экран `/downloads/:tab?`** — шапка со сводкой и вкладки (`Tabs`), счётчик на каждой:
   | Вкладка | Состояния | Содержимое строки | Действия |
   |---|---|---|---|
   | **Требуют внимания** (по умолчанию, если не пуста) | `missing`, `partial` | обложка, альбом, артист, «найдено N из M», причина человеческим текстом, число попыток, когда следующий автоповтор, ошибки источников (раскрываются) | Повторить поиск · Источники (→ `/album/:id/sources`) · Свой magnet |
   | **В поиске** | `searching` | прогресс этапа (`job.progress`), число активных задач | — |
   | **Загружаются** | `downloading` + закреплённые в очереди/ожидании источника | прогресс (байты, %), скорость, пиры, состояние закрепления (`queued / downloading / waiting_source / failed`) | Отменить (снять закрепление) |
   | **Доступны** | `available` | найдено, не скачано на сервер (играет потоково) | Скачать на сервер |
   | **Скачаны** | `downloaded` | размер, закреплён ли | Снять закрепление / удалить файлы |
   | **Торренты** | — | перенос `downloads-view.tsx`: торренты движка, состояние, скорость | Пауза / возобновить |
   | **Задачи** | — | упавшие задачи: вид, к чему относится (альбом/артист ссылкой, если есть в payload), ошибка, попытки | Повторить |
   Списки альбомов — виртуализированные, догружаются при прокрутке. Причины (`no_torrents`, `dead_torrents`, `no_match`, `search_failed`) и исходы — через i18n, с подсказкой «что можно сделать».
3. **Массовые действия (шапка вкладки «Требуют внимания»).** «Повторить поиск для всех (N)» с флажком «перепроверить мёртвые раздачи» (`reset_dead`) и подтверждением при N > 50;
   выбор нескольких строк (чекбоксы, «выбрать все загруженные») → «Повторить для выбранных». После запуска — toast «Поставлено в очередь: N», строки переходят во вкладку «В поиске» по событиям.
4. **Глобальные действия (шапка экрана).** «Пауза всех загрузок / Возобновить» (состояние `paused` из `GET /api/downloads`), «Скачать всё доступное» (закрепить все `available`; подтверждение с оценкой числа альбомов).
   Заполненность хранилища сервера одной строкой (`GET /api/storage`) со ссылкой на раздел настроек.
5. **Кнопка «Скачать на сервер» на экране альбома** (шаг 39): состояния — нет / в очереди / прогресс / скачан (с меню «Убрать с сервера»). Данные — `useAlbumAcquisition(albumId)` (запрос списка с фильтром по альбому не предусмотрен API —
   используй состояние из открытых списков, а при отсутствии — вычисли из треков store: все `ready` → скачан; прогресс — из `live`-store по `download.progress`; признак закрепления получай запросом `GET /api/acquisition?album_ids=` **только если** такой параметр есть в схеме, иначе добавь его в бэкенд: фильтр `album_ids` (список до 100 id) в `GET /api/acquisition` с тестом — единственная правка бэкенда в шаге).
6. **Значок в навигации.** У пункта «Загрузки» — число альбомов, требующих внимания (из сводки; запрос сводки — при старте и по событиям, не опросом).
7. **Настройки.** В список разделов настроек (шаг 43) добавить ссылку «Загрузки и поиск» → `/downloads`; в разделе «Хранилище сервера» — ссылку на вкладку «Скачаны».
8. **Маршруты.** Зарегистрировать `/downloads`, `/downloads/:tab` (пункт навигации появится сам). Старый адрес `/settings/downloads` → перенаправление на `/downloads/torrents`.
9. **Мок и e2e.** Мок реализует контракты шагов 26, 32, 33 над своими данными: вычисление состояния по трекам, закрепления, имитация загрузки (служебный `POST /__test/progress`), сводка, задачи.
10. **i18n.** Все новые строки — во все языки.

## Тесты (обязательные)

Unit/компонентные:
- вычисление вкладки по умолчанию; счётчики из сводки; тексты причин и исходов для каждого кода; формат «следующий повтор через …»;
- бесконечный список: догрузка страниц, отсутствие дублей при инвалидации посреди прокрутки;
- события: 20 `acquisition.changed` за 200 мс → один перезапрос; `download.progress` обновляет строку без запроса;
- массовый повтор: тело запроса для «всех» и для выбранных, `reset_dead`, подтверждение при N > 50;
- кнопка «Скачать на сервер»: все состояния, оптимистичное переключение и откат при ошибке;
- пауза всех: состояние кнопки из ответа, блокировка на время запроса;
- задачи: повтор → строка исчезает; 409 от сервера → понятное сообщение.

E2E:
- альбом не найден → виден во «Требуют внимания» с причиной → «Повторить поиск» → переходит в «В поиске» → (мок находит) → «Доступны»;
- «Повторить для всех» → счётчик вкладки обнуляется, значок в навигации исчезает;
- «Скачать на сервер» на экране альбома → прогресс растёт (мок) → «Скачан»; на экране загрузок альбом прошёл «Загружаются» → «Скачаны»;
- пауза всех → строки показывают «на паузе» → возобновить;
- вкладка «Торренты»: пауза одного торрента (перенос старого сценария);
- упавшая задача → «Повторить» → исчезла;
- мобильный размер: вкладки прокручиваются горизонтально, действия строки доступны через меню.

## Критерии приёмки

```
just client-check && just client-test && just client-cov && just client-e2e
just db-up && just backend-test && just openapi && just client-gen-api    # если правился бэкенд (п. 5)
```

Ручная проверка на реальном бэкенде (если доступен): добавить артиста, дождаться поиска, убедиться, что вкладки и счётчики соответствуют действительности. Результат — в Журнал.

## Не входит в шаг

- Скачивание на устройство (46–47) — это отдельное хранилище и отдельная вкладка, её добавит шаг 47.
- Изменение логики приобретения на сервере.

## Подводные камни

- Не опрашивай сервер таймером там, где есть события: опрос оправдан только для списка торрентов движка (он не публикует событий).
- Инвалидация бесконечного списка перезапрашивает все загруженные страницы — при длинном списке это дорого; ограничь `maxPages` или перезапрашивай только первую страницу и сводку, а строку конкретного альбома обновляй точечно.
- «Скачать всё доступное» при большой библиотеке — тысячи закреплений: это один запрос на альбом; выполняй с ограничением параллельности (4) и показывай прогресс, либо добавь на бэкенд массовый эндпоинт — если выбираешь второе, оформи как правку бэкенда с тестами и запиши в Журнал.
- Состояние «Загружаются» на сервере и «Скачано на устройство» на клиенте — разные вещи; в текстах всегда уточняй «на сервер».
