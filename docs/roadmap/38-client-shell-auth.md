# Шаг 38 — Оболочка: вход, навигация, live-соединение, темы, язык

**Фаза 2 · Зависит от:** 37 · **Закрывает находку:** F1 (навигация)

## Зачем

Каркас приложения, в который следующие шаги вставляют экраны: маршруты, боковая панель и нижняя
панель вкладок, экран входа, постоянное WebSocket-соединение, индикаторы связи и синхронизации.
После шага приложение запускается, проходит авторизацию, синхронизирует библиотеку и мгновенно
переключается между (пока пустыми) экранами.

## Что сделать

1. **Маршруты (`src/router.tsx`, `createBrowserRouter`).** Все маршруты объявляются сейчас; экраны, которых ещё нет, не создаются — маршрут добавит свой шаг.
   На этом шаге: `/login`, корневой макет приложения и страница «не найдено». Таблица целевых маршрутов (для справки следующим шагам):
   `/` (39), `/library` и `/library/:tab` (39), `/artist/:id` (39), `/album/:id` (39), `/album/:id/sources` (42), `/playlist/:id` (42),
   `/search` (40), `/settings` и `/settings/:section` (43), `/downloads` и `/downloads/:tab` (44).
   Экраны входят в основной бандл (без `lazy`) — переход не должен ждать загрузки кода; исключения оговариваются в своих шагах.
2. **Сессия — `src/lib/auth/`.** Store `session`: `unknown | anonymous | authenticated`, `authRequired`.
   - старт: `GET /api/auth/session`; результат кэшируется в `localStorage['nimbus:session']`, чтобы без сети приложение открывалось с последним известным состоянием;
   - `login(token)` → `POST /api/auth/login` (cookie ставит сервер) → `authenticated` → `bootstrap()` данных;
   - `logout()` → `POST /api/auth/logout`, остановка движка, очистка IndexedDB и локальных данных плеера, переход на `/login`;
   - `onUnauthorized` из API-клиента и движка синхронизации → `anonymous` и переход на `/login?next=<текущий путь>`.
   Экран `/login`: перенос формы из `web/app/login/login-form.tsx` (поле токена, ошибка «неверный токен», блокировка кнопки на время запроса); после входа — на `next`.
   Защита маршрутов: `anonymous` при `authRequired` → `/login`; `/login` при `authenticated` → `/`.
3. **Макет приложения — `src/components/app-shell.tsx`.** Боковая панель (настольная), область контента, место под панель плеера (пустой контейнер с `data-slot="player"`; плеер монтирует шаг 41),
   нижняя панель вкладок (мобильная). Отступы безопасных зон (`env(safe-area-inset-*)`), высота `100dvh`, прокручивается только область контента. Перенеси `Sidebar`, `MobileTabBar`, `PageLayout`.
   Пункты навигации: Главная, Поиск, Библиотека, Загрузки, Настройки — пункт показывается, только когда его маршрут существует (массив пунктов фильтруется по зарегистрированным маршрутам; шаги 39–44 ничего в оболочке не правят, только добавляют маршрут).
4. **Навигация.** `NavLink` с активным состоянием; переходы используют View Transitions (`viewTransition` у ссылок React Router) с теми же анимациями, что в `globals.css`; при `prefers-reduced-motion` — без анимаций.
   Восстановление прокрутки на каждый экран (перенос `use-scroll-restoration`: позиция запоминается по ключу истории и восстанавливается при «назад»).
   Заголовок вкладки: хук `useTitle(title)` → `«<title> · Nimbus»`.
5. **Live-соединение — `src/lib/live/socket.ts`** (чистый модуль) + хук `useLiveEvent(type, handler)`.
   Перенос логики `live-events-provider.tsx`: подключение к `wsUrl('/api/ws')` (шаг 36; в PWA — тот же origin, cookie), переподключение с экспоненциальной паузой и джиттером,
   пауза при скрытой вкладке не делается (нужны события для плеера), состояние `connecting | open | closed`.
   Каждое событие передаётся в `engine.handleEvent`, затем подписчикам. При (пере)подключении — `engine.requestSync('ws-open')`. Соединение живёт только в состоянии `authenticated`.
6. **Индикаторы.** `ConnectionIndicator` (перенос) + состояние синхронизации: первая загрузка библиотеки показывает прогресс («Загружаем библиотеку… N»),
   дальше — ненавязчивый статус в боковой панели (синхронизировано / синхронизация / нет связи / ошибка с кнопкой «Повторить»). `OfflineIndicator` (перенос, по `navigator.onLine` + состоянию сокета).
7. **Первый запуск.** Пока `hydrated === false` — каркас оболочки со skeleton в области контента (не пустой экран). Если IndexedDB пуста и снимок ещё идёт — экран загрузки с прогрессом. Если IndexedDB недоступна — предупреждение-toast один раз за сессию.
8. **Настройки внешнего вида** пока живут в боковой панели: `ThemeToggle`, `LanguageSelect` (перенос; полноценный раздел — шаг 43).
9. **Ошибки.** Корневой `ErrorBoundary` (перенос `error-boundary`/`error-state`) с кнопками «Перезагрузить» и «Сбросить локальные данные» (`resetAndResync`); `errorElement` маршрутов; страница 404.
10. **Мок и e2e.** В `tests/mock-backend.ts`: `/api/auth/session`, `/api/auth/login|logout`, `/api/sync/snapshot`, `/api/sync/changes`, `/api/ws` (рассылка событий по служебному `POST /__test/emit`, изменение данных — `POST /__test/mutate`, сброс — `POST /__test/reset`).
    Начальные данные мока — небольшая библиотека (3 артиста, 8 альбомов, ~80 треков, 2 плейлиста) из общей с unit-тестами фабрики.

## Тесты (обязательные)

Unit/компонентные:
- сессия: все переходы состояний; кэш в `localStorage`; `logout` чистит IndexedDB и останавливает движок; 401 посреди работы → `/login?next=…`;
- сокет: переподключение с растущей паузой (fake timers), сброс паузы после успешного соединения, доставка событий подписчикам и в движок, `requestSync` при открытии, закрытие при выходе;
- защита маршрутов; `NavLink` активен на вложенных путях; фильтрация пунктов навигации по маршрутам;
- восстановление прокрутки: «назад» возвращает позицию, новый переход начинает сверху;
- индикаторы: каждое состояние синхронизации и связи отображается своим текстом.

E2E (Playwright, мок):
- вход: неверный токен → ошибка; верный → оболочка; перезагрузка страницы не требует входа; выход возвращает на `/login`;
- авторизация выключена (`auth_required: false`) → сразу оболочка;
- библиотека синхронизируется при первом входе (виден прогресс, затем статус «синхронизировано»); после перезагрузки запрос снимка **не** повторяется (проверить по журналу запросов мока), идёт только дельта;
- обрыв WebSocket → индикатор «нет связи» → восстановление → индикатор исчез и выполнена дельта;
- мобильный размер (390×844): нижняя панель видна, боковая скрыта; настольный — наоборот.

## Не входит в шаг

- Содержимое экранов (39+), плеер (41), командная палитра (40), service worker (45).

## Подводные камни

- Cookie `nimbus_token` — `HttpOnly`: клиент не может её прочитать; единственный источник правды о входе — `GET /api/auth/session` и ответы 401.
- В dev-режиме запросы идут через прокси Vite (тот же origin) — CORS и `SameSite` не мешают; не добавляй `Authorization`-заголовок и не храни токен в `localStorage`.
- React StrictMode в dev дважды запускает эффекты: сокет и движок должны создаваться вне эффектов (синглтоны из `app-data.ts`), эффект только подписывается/отписывается.
- Исправления для iOS выглядят как «магия» (подталкивание прокрутки, `lvh`) — не упрощай их; проверь по комментариям в исходных файлах, что перенесено всё.
