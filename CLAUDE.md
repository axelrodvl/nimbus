# Nimbus

Веб-плеер: метаданные из MusicBrainz, музыка — потоково из торрентов. Фронтенд — React SPA (`client/`, Vite, bun), которую бэкенд раздаёт сам, бэкенд — Rust (`backend/`), БД — PostgreSQL.

## Главное правило

Вся работа идёт по дорожной карте в `ROADMAP.md` (шаги 25–55: фазы 0–3 — бэкенд и PWA, фаза 4 — нативные оболочки iOS/Android/desktop; старый `PLAN.md`, шаги 01–23, выполнен и оставлен как история). Правила разработки, обязательные для любого изменения, — `docs/DEVELOPMENT.md`.

Когда пользователь говорит **«запусти следующий шаг»** (или «следующий шаг», «выполни следующий шаг плана», «продолжай план»), строго следуй протоколу из раздела «Как работать» в `ROADMAP.md`:

1. найди незавершённый шаг `[~]`, иначе — первый `[ ]` с выполненными зависимостями;
2. прочитай `docs/DEVELOPMENT.md`, файл шага `docs/roadmap/NN-*.md`, последние записи Журнала;
3. выполни шаг целиком, напиши все тесты из шага, прогони критерии приёмки;
4. проведи ревью изменений по `docs/DEVELOPMENT.md` §7, исправь найденное, прогони тесты снова;
5. обнови статус и Журнал в `ROADMAP.md`, закоммить `step NN: ...`;
6. остановись и отчитайся. Один запрос = один шаг.

## Коммиты

После внесения любых изменений в репозиторий (код, документация, конфиги — не только шаги плана) обязательно делай коммит. Не оставляй рабочее дерево с незакоммиченными правками. Сообщение коммита — короткое, в стиле существующей истории (`area: что сделано`, для шагов плана — `step NN: ...`).

## Полезные команды

- `./scripts/build.sh` — собрать образ (сборка Rust и клиента на bun идёт внутри контейнера; на хосте нужен только Docker)
- `./scripts/start.sh` — поднять весь стек (Postgres + `nimbus`) из собранного образа (http://localhost:8000)
- `./scripts/stop.sh` — опустить контейнеры (`--purge` — ещё и том БД)
- `./scripts/prune-target.sh [ГБ]` — ротация `backend/target`: удаляет его, если он больше лимита (20 ГБ); вызывается из `just backend-test` / `backend-cov` и хуком Claude после каждой Bash-команды (`.claude/settings.json`). Если запускаешь `cargo` напрямую — вызывай перед сборкой, иначе диск забивается устаревшими бинарниками
- `just db-up` — поднять Postgres (docker compose)
- `just backend` — запустить бэкенд
- `just client` — запустить клиент (`client/`, Vite, http://localhost:5173)
- `just client-test` / `just client-cov` / `just client-e2e` — тесты, покрытие и e2e клиента (мок-бэкенд)
- `just client-audit` — аудит интерфейса: матрица скриншотов (`client/test-results/audit/`), axe, клавиатура, reduced motion; `just client-perf` — бюджеты производительности на 60 000 треков
- `just e2e` — сквозной сценарий на полном стеке в Docker (`client/tests/stack/`)
- `just test` — все тесты
- `just check` — fmt + clippy + lint + typecheck
- `just cov` — покрытие бэкенда с проверкой порога (`backend/coverage-threshold.txt`)

(Команды появляются по мере выполнения шагов; актуальный список — в `justfile`.)
