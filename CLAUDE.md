# Nimbus

Веб-плеер: метаданные из MusicBrainz, музыка — потоково из торрентов. Фронтенд — Next.js (`web/`, форк next-beats), бэкенд — Rust (`backend/`), БД — PostgreSQL.

## Главное правило

Вся работа идёт по плану в `PLAN.md`. Когда пользователь говорит **«выполни следующий шаг плана»** (или «следующий шаг», «продолжай план»), строго следуй протоколу из раздела «Как работать с этим планом» в `PLAN.md`:

1. найди первый невыполненный шаг с выполненными зависимостями (или незавершённый `[~]`);
2. прочитай `PLAN.md` → «Соглашения», файл шага `docs/plan/NN-*.md`, последние записи «Журнала»;
3. выполни шаг целиком, прогони критерии приёмки;
4. обнови статус и Журнал в `PLAN.md`, закоммить `step NN: ...`;
5. остановись и отчитайся. Один запрос = один шаг.

## Коммиты

После внесения любых изменений в репозиторий (код, документация, конфиги — не только шаги плана) обязательно делай коммит. Не оставляй рабочее дерево с незакоммиченными правками. Сообщение коммита — короткое, в стиле существующей истории (`area: что сделано`, для шагов плана — `step NN: ...`).

## Полезные команды

- `./scripts/build.sh` — собрать все образы (сборка Rust и Next.js идёт внутри контейнеров; на хосте нужен только Docker)
- `./scripts/start.sh` — поднять весь стек из собранных образов (http://localhost:8000)
- `./scripts/stop.sh` — опустить контейнеры (`--purge` — ещё и том БД)
- `just db-up` — поднять Postgres (docker compose)
- `just backend` — запустить бэкенд
- `just web` — запустить фронтенд
- `just test` — все тесты
- `just check` — fmt + clippy + lint + typecheck

(Команды появляются по мере выполнения шагов; актуальный список — в `justfile`.)
