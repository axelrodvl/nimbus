# Nimbus

Веб-плеер: метаданные из MusicBrainz, музыка — потоково из торрентов. Фронтенд — React SPA (`client/`, Vite, bun), которую бэкенд раздаёт сам, бэкенд — Rust (`backend/`), БД — PostgreSQL.

## Главное правило

Вся работа идёт по дорожной карте в `ROADMAP.md` (шаги 25–55: фазы 0–3 — бэкенд и PWA, выполнены к версии 1.0.0; впереди фаза 4 — нативные оболочки iOS/Android/desktop, шаги 52–55; старый `PLAN.md`, шаги 01–23, выполнен и оставлен как история). Правила разработки, обязательные для любого изменения, — `docs/DEVELOPMENT.md`. Задачи вне плана — `docs/backlog.md`; эксплуатация и переменные окружения — `docs/operations.md`.

Когда пользователь говорит **«запусти следующий шаг»** (или «следующий шаг», «выполни следующий шаг плана», «продолжай план»), строго следуй протоколу из раздела «Как работать» в `ROADMAP.md`:

1. найди незавершённый шаг `[~]`, иначе — первый `[ ]` с выполненными зависимостями;
2. прочитай `docs/DEVELOPMENT.md`, файл шага `docs/roadmap/NN-*.md`, последние записи Журнала;
3. выполни шаг целиком, напиши все тесты из шага, прогони критерии приёмки;
4. проведи ревью изменений по `docs/DEVELOPMENT.md` §7, исправь найденное, прогони тесты снова;
5. обнови статус и Журнал в `ROADMAP.md`, закоммить `step NN: ...`;
6. остановись и отчитайся. Один запрос = один шаг.

## Коммиты

После внесения любых изменений в репозиторий (код, документация, конфиги — не только шаги плана) обязательно делай коммит. Не оставляй рабочее дерево с незакоммиченными правками. Сообщение коммита — короткое, **на английском** (`area: what was done`, для шагов плана — `step NN: ...`). Старая история на русском — это нормально, переписывать её не нужно.

## Релизы

Когда пользователь просит релиз («сделай релиз», «выпусти версию» и т. п.), делай всё сам, без уточнений и подтверждений:

1. Номер версии: если не назван — выбери по semver по изменениям с прошлого тега (`git log vПРОШЛЫЙ..HEAD`): только исправления → patch, новое → minor.
2. Напиши `docs/releases/vX.Y.Z.md` на английском по `docs/releases/TEMPLATE.md` (черновик — `./scripts/release-notes.sh --draft`; пункты — с точки зрения пользователя, не коммиты). Проверь `./scripts/release-notes.sh vX.Y.Z`.
3. Подними версию (`backend/Cargo.toml`, `Cargo.lock`, `client/package.json`, `client/openapi.json`; порядок — README, «To publish a release») и добавь запись в `CHANGELOG.md`.
4. Прогони проверки (`just check`, нужные тесты), закоммить `release: version X.Y.Z`, поставь тег `git tag -a vX.Y.Z -m vX.Y.Z` и запушь `git push origin main vX.Y.Z`.
5. Отчитайся: версия, ссылка на notes, статус workflow `Release` (`gh run list`), если доступно.

## Полезные команды

- `./start.sh [версия]` / `./stop.sh [--purge]` — в корне: стек из ОПУБЛИКОВАННЫХ образов `ghcr.io/axelrodvl/nimbus` (без сборки). Ниже `scripts/*` — для разработки, с локальным образом `nimbus:local`; оба набора — один compose-проект `nimbus`, одновременно только один
- `./scripts/build.sh` — собрать образ (сборка Rust и клиента на bun идёт внутри контейнера; на хосте нужен только Docker)
- `./scripts/start.sh` — поднять весь стек (Postgres + `nimbus`) из собранного образа (http://localhost:8000)
- `./scripts/stop.sh` — опустить контейнеры (`--purge` — ещё и том БД)
- `./scripts/prune-target.sh [ГБ]` — ротация `backend/target`: удаляет его, если он больше лимита (20 ГБ); вызывается из `just backend-test` / `backend-cov` и хуком Claude после каждой Bash-команды (`.claude/settings.json`). Если запускаешь `cargo` напрямую — вызывай перед сборкой, иначе диск забивается устаревшими бинарниками
- `just db-up` — поднять Postgres (docker compose)
- `just backend` — запустить бэкенд
- `just client` — запустить клиент (`client/`, Vite, http://localhost:5173)
- `just client-test` / `just client-cov` / `just client-e2e` — тесты, покрытие и e2e клиента (мок-бэкенд)
- `just client-audit` — аудит интерфейса: матрица скриншотов (`client/test-results/audit/`), axe, клавиатура, reduced motion; `just client-perf` — бюджеты производительности на 60 000 треков
- `just e2e` — сквозной сценарий на полном стеке в Docker (`client/tests/stack/`)
- `just load` / `just resilience` / `just soak` — нагрузка (~54 000 треков), отказы и длительный прогон на полном стеке с фейками (вручную; `docs/DEVELOPMENT.md` §8)
- `just docs-check` — документация ↔ код (OpenAPI ↔ `docs/api.md`, `NIMBUS_*` ↔ `docs/operations.md`/`.env.example`); входит в `just check`
- `just test` — все тесты
- `just check` — fmt + clippy + lint + typecheck
- `just cov` — покрытие бэкенда с проверкой порога (`backend/coverage-threshold.txt`)

(Команды появляются по мере выполнения шагов; актуальный список — в `justfile`.)
